# ALMEAA — أمر استلام وتنفيذ كامل إلى Antigravity

**نوع الوثيقة:** تكليف تنفيذي شامل، وليس إقرار اكتمال.  
**لقطة GitHub المفحوصة:** 21 نوفمبر 2026.  
**المسؤول عن التنفيذ والتنسيق:** Antigravity وحده. يمكنه تفويض تحليل/مراجعة/تنفيذ محدود لوكلاء متخصصين داخل بيئته، بشرط بقاء مسؤوليته كاملة، وعدم تداخل الكتابة، واستقلال مراجعة القبول عن من كتب التغيير. **ليس مطلوبًا تشغيل Codex أو DeepSeek أو Herons من الخارج** لإنجاز أي خطوة؛ إن لم تتوفر أداة متخصص، يؤدي Antigravity الدور بالتتابع ويعلن حدود الاستقلالية بوضوح.

## الحكم الملزم

الهدف هو نقل **كل تجربة ALMEAA القديمة المعتمدة** إلى `almeaago` مع الحفاظ على تجربة المستخدم، البيانات، السلوك، العلاقات، الصلاحيات والنتائج التعليمية، وإصلاح البنية الداخلية باستخدام Go/PostgreSQL/React **دون إعادة تصميم صامت**. كل القدرات والأدوار مدرجة؛ الأمثلة والفشلات الحالية لا تحصر نطاق البرنامج.

- المستودع المستهدف الذي يُسمح الكتابة فيه: `https://github.com/nasef6464/almeaago`.
- المستودع القديم للقراءة والمقارنة فقط: `https://github.com/nasef6464/almeaacodax`؛ **لا كتابة ولا تعديل بيانات إنتاج أو تشغيل أي ترحيل إنتاجي**.
- المرجع الأعلى للتنفيذ داخل المستهدف: `docs/migration/03_EXECUTION_AND_HANDOFF_PLAN_AR.md` و`AGENTS.md` والعقود التي يشير إليها. هذا التكليف **ملحق تشغيلي، لا Master Plan بديلة**. عند تعارضه مع قواعد أمان أعلى أو طلب مالك أحدث مسجل، أوقف الإجراء المتعارض وسجل القرار.
- عقد المطابقة المرئية: `.agents/rules/no-redesign.md` + `docs/architecture/VISUAL_PARITY_POLICY.md`، مع أحدث `almeaacodax/main` و`docs/MASTER_CONTROL/` هناك.
- مصدر حقيقة البيانات: PostgreSQL؛ المعمارية Modular Monolith. لا تُنقل سلطة التصحيح/الإتقان إلى AI/React ولا تكرر Assessment/Entitlements/Permissions في أكثر من Domain.

## ابدأ بهذه الملفات داخل الحزمة بالترتيب

1. `01_REQUIRED_REPO_FILES_AR.md` — الملفات الأصلية الموجودة في المشروع والتي يجب قراءتها وكيفية استخدامها.
2. `02_EXECUTION_METHOD_AR.md` — طريقة العمل الدقيقة من أول أمر إلى PR والاختبار والدمج.
3. `03_VERIFIED_PROBLEMS_AR.md` — قائمة المشكلات المثبتة، مع ما هو ظن أو غير مثبت.
4. `04_PHASES_ACCEPTANCE_AR.md` — ترتيب المراحل والنتائج المطلوبة قبل الانتقال.
5. `05_SPECIALIST_SKILLS_AR.md` — كيف تدير الاختصاصات داخل Antigravity وتستفيد من المهارات الموجودة في المستودع.
6. `06_PILLARS_AND_OR_AR.md` — المحاور الهندسية والتربوية وبحوث العمليات، ومتى تطبقها.
7. `07_LOCAL_COMMANDS_AR.md` — الأوامر الآمنة الأولى لنظام Windows وGitHub والاختبارات.
8. `registers/` — ملفات CSV/JSON لدفعات العمل، لا تعلن نجاحًا حتى تملأ أدلة كل حالة.
9. `templates/` — قوالب PR والبوابات وملحق AGENTS المقترح ومهمة الوكيل المتخصص.
10. `references/` — تقارير المستخدم الأربعة للتفسير؛ ابدأ بالمستودعات الحية قبل اعتبار أي حالة قديمة صالحة.

## شغل لازم يوقف فورًا

- دمج PR قديم بكامل محتواه بلا مقارنة مع `main` الحالية.
- حذف/إسكات اختبارات أو تعطيل Assertions أو تسمية SKIPPED «PASS» أو توسيع صلاحيات 403 بغرض تمرير اختبار.
- تغيير شكل موقع Legacy أو تقسيم الإدارة وSkills Center من غير اعتماد صريح.
- كتابة بيانات إنتاج أو نقل Mongo الفعلي أو نشر Vercel/Render/Neon/Cloudinary/R2 دون تصريح نشر مستقل.
- إضافة أي ميزة بافتراض أنها موجودة لأن اختبار Track يطلبها: يلزم تحقق من Product Contract والأصل واعتماد المنتج.
- تقديم نسبة تطابق غير محسوبة من حالات أصل/هدف فعلية ومقامات محددة.
- وصف «الوكلاء يعملون» أو «الوثيقة اتكتبت محليًا» بدليل تسليم على GitHub.

## معيار انتهاء الدفعة

لا تقبل كلمة DONE إلا بعد: إعادة إنتاج العيب أو إثبات عدم وجوده، تحديد السلوك الأصلي والمطلوب، إصلاح أصغر نطاق صحيح، اختبار أحمر ثم أخضر أو دليل بديل مبرر، وحدات/تكامل Go/Postgres عند الحاجة، اختبار سلبي للصلاحيات، browser E2E ولقطات مقارنة وفق نوع الشريحة، فحص CI على SHA النهائي، مراجعة مستقلة، تسجيل روابط PR/CI/صور، ثم حالة الدمج الفعلية. **Green build وحده لا يكفي.**

انتهت صلاحية أي تقرير يخالف أحدث Git/CI/live browser. ابدأ التنفيذ الفعلي فور فحص السياق والتصنيف؛ لا تحوّل الطلب إلى ورقة تخطيط إضافية بلا عمل.
