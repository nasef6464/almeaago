## 0. القرار التنفيذي

يُبنى النظام في **Go** لا في Codax؛ فلا نضيف دينًا تقنيًا إلى المصدر الذي نرحّله ثم ننقله مرة أخرى. يُستعمل Codax للمعاينة والمطابقة الدقيقة للواجهات والرحلات والمفاهيم والحقوق والتفاصيل المفقودة في Go. نضيف إلى Go تدريجيًا دون تغيير سلطة التصحيح أو التراخيص أو نسب الإتقان التاريخية دون عقد معايرة وتوافق. التنفيذ جزئي حتى يثبت كل مسار بوظائف E2E على بيانات PostgreSQL معزولة، لا يكفي اعتماد التصميم.

الخلاصة: محرك واحد للحقائق التعليمية والقرار، وأوجه عرض متعددة في المسار الذكي وخططي وتقاريري ونتائج الاختبار والتأسيس والمدارس وأولياء الأمور والإدارة؛ دون بناء لوحات موازية أو نسخ بنك الأسئلة.

## 1. العقد التعليمي الملزم

1. الهيكل: `Path → optional Stage/Level → Subject → Main Skill → Subskill → Primary Question Skill`. لو لم توجد مهارة فرعية يسمح بالربط بالمهمة الرئيسية. السؤال يملك مهارة أساسية محددة مؤرخة وذات نسخة؛ أي مهارات ثانوية محتملة لا تدخل إتقانها تلقائيًا دون سياسة تبرر إسناد الدليل.
2. المهارة وحدة القياس. التأسيس/الموضوع/الدرس/الفيديو كيان تعليمي مستقل، ويربط بالمهارة عبر علاقة ثابتة مؤهلة للنشر. لا نخلط بين الشجرة التعليمية والعلاقة التأسيسية بين المهارات (DAG prerequisites).
3. الطالب قد يدرس مسارات متعددة: مفتاح التقدم `(student, path, subject, skill)`. المشابهة بين مسارين ليست ترخيصًا لتبادل درجة الإتقان.
4. السؤال وأصله/نسخته مفتاح إجابة سلطوي، والاختبار والمحاولة يخزنان مراجع immutable وتصححان خادميًا. تجربة الاختبار والتدريب والحصة والمراجعة تؤدي إلى أدلة مختلفة الأهلية.
5. غياب الدليل وغياب السؤال المعتمد لا يعنيان ضعفًا. التقرير يفصل بين `not_measured`, `insufficient_evidence`, `measured_weakness`, `adequate/mastered`, `stale_evidence`, و`blocked_by_content`، و`not_applicable`.
6. مؤشر إتقان، وتغطية، وثقة، وحداثة، وأداء زمني، وجاهزية هدف: مقاييس مستقلة؛ لا نخلطها بنقطة مضللة أو بزعم مطابقة درجات رسمية.
7. المحتوى الموصى به يُفحص نشره واستحقاقه وصلاحية فتحه عند الطلب. لا يصير فتح الفيديو أو السؤال مع المساعد دليل إتقان مستقل.
8. المدارس: مصدر دليل الاختبار المدرسي/الحصة/تعلم المنصة ذاتيًا يظل مميزًا، ولا ينقل دليل طالب إلى زميله أو إلى مدرسة أخرى.
9. المحافظة على تجربة Legacy وتدرج المهارات والـRTL 390/820/1440؛ تحسين التصميم المصرح دون إعادة رسم كاملة.

## 2. تجربة الطالب — ربط المداخل القائمة

| المدخل | المحتوى الديناميكي المقترح | الأزرار/الإجراءات | مصدر المعلومة |
|---|---|---|---|
| `لوحة الطالب /dashboard`، نظرة عامة | هدف المسار المختار، حالة الجاهزية مع السبب والتاريخ، أقرب موعد، **خطوة واحدة اليوم**، تغير بعد آخر قياس | `ابدأ خطوة اليوم`، `اختر مسارًا`، `لماذا هذه التوصية؟` | Readiness/Next Action |
| `مساراتي` | بطاقات المسارات، لكل مسار عدد المواد، التغطية ودليل التقدم؛ لا دمج درجات بين المسارات | `افتح المادة`، `تفاصيل المهارات` | Taxonomy + Progress |
| `المسار الذكي` `/dashboard?tab=smart-path` | خريطة مادة > رئيسية > فرعية، حالة/ثقة/زمن كل مهارة، فلاتر: غير مقاس، ضعيف مثبت، يحتاج تثبيت، متقن | `افتح التأسيس`، `ابدأ تدريبًا`، `اختبار تشخيصي`، `أعد القياس`، `أسئلتي للمراجعة`، `أضف إلى خطتي` | Evidence + Diagnostic + content entitlements |

| `تقاريري` `/reports` | مسار، مادة، فترة، مصدر أدلة، كل اختبار وتغير كل مهارة، التغطية/الثقة وأسباب الحكم؛ مقارنة حديث/تراكمي | `تحليل المهارات`، `عرض الأدلة`، `راجع الأسئلة`، `افتح العلاج`، `طباعة/تصدير` حسب القائم | Reporting projections |
| `اختباراتي ونتائجي` `/assessment-results` | بعد التسليم تظهر مهارات الاختبار وما تغيّر في الجاهزية وما لم يُقَس | `راجع الأخطاء`، `افتح المهارة`، `ابدأ علاجًا`، `إعادة قياس مؤهلة` | Assessment + Learning |
| `التأسيس/المادة` | شريط سياقي «تحتاج هذه المهارة» أو «مراجعة تثبيت» مع خيار عدم عرضه | `ابدأ الدرس`، `تدرب على المهارة`، `أضف للخطة` | Content links + diagnosis |
| `أسئلتي للمراجعة` `/review` | أخطاء وحفظ ومراجعة متباعدة مع عدم ازدواج البطاقة | `تدرّب على هذه الأسئلة`، `أعد القياس بأسئلة جديدة` | Review library |
| `الإشعارات` | تنبيهات مفيدة مرتبطة بموعد مهمة أو قياس أو تغيير يستحق الإشعار | `افتح المهمة`، `تأجيل التذكير` | Notifications policies |

**القاعدة البصرية:** بطاقة ملخص خفيفة، سبب واضح، إجراء رئيسي واحد؛ التفاصيل في drill-down، واسم المادة والمسار محفوظان بين الصفحات؛ حالات Loading/Empty/Error/Forbidden/Stale صريحة. لا أزرار تذهب إلى صفحات وهمية ولا توصية hardcoded بالقدرات عند غياب بيانات.

### حالات الجاهزية التي يراها الطالب

- `NEEDS_MEASUREMENT`: «لم نقس مهارات كافية بعد»؛ الزر `ابدأ قياس المهارات الناقصة`.
- `INSUFFICIENT_EVIDENCE`: «إجاباتك الحالية لا تكفي للحكم»؛ الزر `أكمل قياسًا مستقلًا`.
- `NEEDS_FOUNDATION`: «تحتاج تأسيسًا في ...»؛ الزر `افتح التأسيس`.
- `NEEDS_PRACTICE`: «تحتاج تدريبًا موجهًا في ...»؛ الزر `ابدأ التدريب`.
- `READY_FOR_RECHECK`: «الخطوة التالية إعادة قياس»؛ الزر `أعد القياس`.
- `READY_FOR_GOAL`: «مستعد وفق معيار المئة المحدد» مع توضيح شرط الهدف والفترة؛ الزر `راجع الخطة`.
- `STALE/UNKNOWN`: «آخر قياس قديم/تعذر تحديث التحليل»؛ لا تعرض نجاحًا أو فشلًا من كاش قديم.

## 3. ولي الأمر — `/parent-dashboard`

**موجود في النسخة القديمة:** `متابعة الأبناء`، `نتائج الأبناء`، `المهارات الضعيفة`، `تقرير مبسط` و`ربط طالب`. وفي Go توجد صفحات `ParentDashboardPage` مع ملخص وتقرير أسبوعي وأقسام نتائج ومهارات.

**التطوير داخل الأقسام الحالية:** محدد ابن + مسار + مادة؛ بطاقة «أين يحتاج ابني المساعدة؟»، سبب الحالة وعدد الأدلة وآخر تحديث، ما أنجز هذا الأسبوع، النشاط القادم، تقدم خطة مدرسية معتمدة، مؤشر الالتزام دون لوم، وخط زمني موجز «تقييم → تأسيس → إعادة قياس».

**الأزرار:** `اختر الابن`، `عرض تقرير الأسبوع`، `افتح مهارات تحتاج متابعة`، `عرض خطة الأسبوع`، `عرض آخر نتيجة`، `تذكير الابن` فقط عبر مسار إشعار مصرح؛ `تنزيل تقرير` وفق السياسة. لا يحق لولي الأمر تغيير الدرجات أو اعتماد إتقان أو رؤية أبناء آخرين أو تكليفات مدرسة غير مخوّل بها. إذا كان ربط الابن غير نشط لا يُظهر بياناته.

## 4. المعلم — `/school-teacher-dashboard`

**المكان:** لوحة «مادتي وفصولي» القائمة، بجوار `أدلة التعلم`، `مهارات الحصص` و`اختباراتي وتكليفاتي`؛ لا لوحة تحليل موازية.

**المشهد:** فلاتر المدرسة المصرح بها/الفصل/المادة المسندة/الفترة/مصدر القياس/المحور/حالة الأدلة. جدول خريطة رئيسية > فرعية يوضح `طلاب لهم دليل/إجمالي المستهدفين`, `ضعف مثبت`, `غير مقاسين`, `تغطية`, `متوسط الإتقان المؤهل` ومؤشر الاتجاه. زر drill-down يفتح قائمة الطلاب المصرح بهم فقط.

**الأزرار:** `اعرض مهارات فصلي`، `اعرض الطلاب المحتاجين`، `تفاصيل الدليل`، `اقترح تدريبًا`، `كوّن مجموعة تقوية`، `معاينة النشاط`، `إسناد بعد الاعتماد`، `حدد إعادة قياس`، `تابع الإنجاز`، `قارن قبل وبعد`. لا إسناد لمحتوى غير منشور أو غير متاح، ولا تكليف طالب خارج الفصل والمادة.

## 5. المشرف — `/supervisor-dashboard` و`/supervisor-dashboard/interventions`

**المكان:** الأقسام الحالية `خريطة المهارات`، `الاختبارات والتحليل`، `تقارير الأداء`، `تعلم الطلاب وجاهزيتهم` و`التدخلات`.

**المشهد:** ملخص المدارس/الفصول المصرح بها، وأهم المهارات المطلوب قياسها، وأهم المهارات ذات الضعف المثبت، ومجموعات الدعم المقترحة، وحالات التدخل المفتوحة، وعدد الطلاب المقاسين مقابل الإجمالي. مقارنة مصادر القياس (اختبار مدرسي/منصة/حصة) في تبويبات قابلة للتمييز.

**الأزرار:** `اختر المدرسة/الفصل`، `خريطة المهارات`، `افتح ملف الطالب`، `أنشئ/راجع تدخلًا`، `اقترح مجموعة دعم`، `وزع مسؤولية المتابعة` عند التفويض، `راجع نتائج التدخل`، `اعتمد إغلاق التدخل` فقط إن كان مخولًا، `تصدير تقرير`. التقارير بين الفصول تراعي اختلاف مقامات المشاركة، ولا تعرّض أسماء الطلاب خارج النطاق.

## 6. مدير المدرسة — `/school-director-dashboard` و`/school-director-dashboard/interventions`

**المشهد التنفيذي الأول:** عدد الطلاب المستهدفين، عدد من لديهم قياس مؤهل، غير المقاسين، من لديهم احتياج تعليمي مثبت، التدخلات المفتوحة/المغلقة، والتحسن الوصفي بعد إعادة القياس؛ جميعها بحسب هدف/مسار/مادة/فصل/فترة/مصدر، مع عرض المقام والتاريخ وعدم اليقين.

**التفصيل:** خريطة حرارية للمواد والمهارات، فصول تحتاج تشخيصًا أو دعمًا، سعة معلمين، التدخلات التي ينتظر اعتمادها أو تقترب مواعيدها، الفرق بين تحسن الظاهر وبين أثر سببي غير مثبت.

**الأزرار:** `عرض فصول المدرسة`، `أكثر المهارات احتياجًا`، `غير المقاسين`، `افتح خطة تدخل`، `راجع مجموعة التقوية`، `اعتمد/ارفض/عدّل` ضمن الصلاحية، `جدولة جلسات الدعم`، `تقرير الفصل`، `تصدير تقرير المدرسة`. لا تعديل سياسة قياس المنصة ولا نشر سؤال عام من مدير المدرسة.

## 7. مالك المنصة / المدير العام — `/admin-dashboard/reports`

**مكان العرض:** قسم فرعي باسم «ذكاء التعلم والجاهزية» داخل `التقارير والتحليلات`، مع deep-links من `إدارة المسارات`، `مركز المهارات`، `مركز بنك الأسئلة`، `مركز الاختبارات`، `تشغيل المدارس` و`مركز العمليات`. لا قائمة عليا جديدة إلا إذا أثبت اختبار الاستخدام الحاجة.

**التبويبات الستة:**

1. **الصورة العامة:** طلاب فريدون مؤهلون للقياس (B2C وB2B مفصولان)، تغطية المهارات، توزيع حالات الجاهزية لكل هدف، وتغير الفترة وبيانات لم يُحدّث قرارها؛ كل رسم يعلن المصدر والمقام ونطاق الصلاحية.
2. **المسارات والمواد والمهارات:** فلاتر متسلسلة مسار → مادة → رئيسية → فرعية، وهدف، ومدرسة/فصل أو مستقل، وفترة، ونوع التقييم، ومصدر الدليل. أفضل/أضعف المهارات **المقاسة بأدلة مؤهلة**، قائمة «غير مقاس» مستقلة، heatmap، متوسط/وسيط الإتقان والاتجاه وتوزيع عدد الطلاب.
3. **الجودة والفجوات:** أسئلة بلا مهارة/بنسخة غير صالحة، مهارات بلا أسئلة كافية، محتوى غير مرتبط، فجوات الصعوبة، أسئلة محتملة الالتباس أو تعرض زائد، نسبة أسئلة معتمدة مقابل معايرة، فرق المصدر والحصة والتدريب.
4. **الجاهزية والخطط:** حالات الجاهزية حسب الهدف، معدل القرارات غير المدعومة بقياس لاحق، نسبة قبول/إنجاز الخطط، قياس أعباء الوقت، أسباب تعذر الخطط، الأنشطة الأكثر استخدامًا مع فصل النشاط عن أثره.
5. **المدارس والتدخلات:** توزيع الاحتياجات والقياسات حسب مدارس مخوّلة، متابعة المسؤوليات والجلسات وإعادة القياس، مقارنة منصفة عبر عدد المقاسين، وعدم ترتيب مدارس بحكم جزافي.
6. **السياسات والمراقبة:** إصدارات أهداف التعلم وأوزان المهارات، إعداد/معاينة/محاكاة تأثير سياسة، طلب مراجعة تربوية، اعتماد أو إلغاء النشر، Feature Flag، زمن تأخر التحديث، تعثر Worker، سعة الطوابير، كلفة الحل ومخاطر الخصوصية.

**أزرار المدير:** `اختر المسار`، `اختر المادة`، `أكثر المهارات احتياجًا`، `عرض المهارات غير المقاسة`، `افتح بنك الأسئلة للمهارة`، `اعرض روابط التأسيس`، `أنشئ مهمة محتوى`، `راجع صلاحية السؤال`، `اعرض بيانات المدارس`، `أنشئ/راجع مخطط هدف`، `معاينة أثر السياسة`، `طلب اعتماد`، `تفعيل/تعطيل تجريبي`، `مراقبة الأداء`، `عرض سجل التدقيق`، `تصدير المجمّعات`.

**المقياس الخاص بعبارة «أضعف مهارات المنصة»:** لا يعرض ترتيبًا بناءً على أدنى متوسط خام وحده؛ يحتاج مهارة منشورة، عدد طلاب فريدين بالحد الأدنى، عدد محاولات مستقلة مؤهلة، تغطية، وسياق اختبار مماثل، ويعرض عينة غير كافية عند عدم توافرها. عرض أعمدة `الطلاب المستهدفون | من قيسوا | من لديهم ضعف مؤكد | من لم يقاسوا | إجمالي الأدلة | الفترة | التغير` لا مجرد نسبة لونية.

## 8. المدرب/منشئ المحتوى/مدقق القياس

- **المدرب أو معدّ الدرس:** يرى من أدلة منطقية مجمعة ومسموح بها المهارات التي تحتاج شرحًا أو تدريبًا؛ أزرار `جهز درسًا`، `اربطه بالمهارة`، `إرسال للمراجعة`، `تحديث التدريب`. لا يرى الطلاب تلقائيًا إلا بتكليف مدرسي/صلاحية صريحة.
- **مراجع الجودة التربوية:** يفحص تعريف مهارات هدف جديد، وأوزانها وQ-matrix المرتبطة، وحالات نقص البنك أو أسئلة ملتبسة؛ `مراجعة`، `إعادة إلى المؤلف`، `اعتماد الإصدار` حسب صلاحية.
- **منشئ الاختبارات:** اختيارات أسئلة معتمدة حسب المخطط؛ `معاينة نموذج`، `كشف نقص المهارات`، `توليد مسودة`، `مراجعة التوزيع`، `اعتماد ونشر`. لا ينشر solver نموذجًا تلقائيًا.

## 9. رحلة مشتركة End-to-End

1. إداري ينشر مسارًا/مادة/مهارة وموضوع تأسيس وسؤال نسخة معتمدة ومخطط هدف ذي إصدار.
2. الطالب يصل إلى المادة أو اختبار مؤهل؛ الحماية تتحقق من الاستحقاق والمجال.
3. يحل الطالب وينهي `assessment attempt` وتصحيحه على الخادم وفق snapshot نسخ الأسئلة.
4. يولَّد Evidence مرة واحدة ويُحدَّث تقدم المهارة الفرعية، ثم يُحتسب تجميع الرئيسية دون تكرار.
5. يعاد حساب جاهزية أهداف الطالب المتأثرة فقط، مع الإصدار/الوقت/الأسباب وثقة الدليل.
6. يظهر القرار نفسه في لوحة الطالب، المسار الذكي، تقاريري، نتيجة الاختبار، وخططي. يختار الطالب نشاطًا أو إعادة قياس.
7. المعلم/المشرف يرى ضمن تكليفه فقط ملخص احتياج الفصل ويسند دعمًا منشورًا مناسبًا.
8. ينجز الطالب نشاطه ثم يقدم دليل قياس مستقلًا جديدًا؛ تحفظ مقارنة الحالة قبل/بعد، ولا يُنسب التحسن سببيًا للنشاط دون تصميم علمي مناسب.
9. ولي الأمر يرى موجز ابنه، والمدير مدرسـيًا يرى مجموعات، ومالك المنصة يرى مجمّعات كل المسارات بما فيها فجوات الأسئلة والمحتوى.

## 10. النموذج الرياضي

### 10.1 تغطية الهدف

إذا كانت مجموعة المهارات المطلوبة للإصدار `G_v={1..n}`، ووزن كل مهارة `w_i`، وشرط أدلتها `I_i∈{0,1}`:

`Coverage(G_v) = (Σ w_i I_i)/(Σ w_i)` حيث `I_i=1` فقط عند وجود أدلة مؤهلة كافية ومحدثة وفق سياسة الهدف.

التغطية لا تساوي الإتقان. مقامها **كل المهارات المطلوبة** من خريطة التصنيف/الهدف المنشور، لا عدد صفوف Progress التي ظهرت للطالب. لا نضاعف عد المهارة الرئيسية والفرعية داخل مجموع المهارات.

### 10.2 تقدير الإتقان

نحافظ مؤقتًا على scoring الحالي في Go، ونضيف طبقة Evidence Qualification/Versioned Policy. لاحقًا يمكن تجربة BKT/PFA/IRT بعد بيانات معايرة كافية، مع مقارنة Backtest على بيانات لاحقة ومستقلّة. لا يُسمى `P(mastery)` احتمالًا معايرًا إلا باختبار calibration. السؤال المتكرر/الإجابة بمساعدة/العائلة الواحدة لا ترفع الثقة كالمحاولات المستقلة؛ الـQ-matrix متعدد المهارات يحتاج سياسة attribution واختبارات قبل تفعيل عدة تحديثات.

### 10.3 تجميع المهارات

`MainSkill` يظهر حالة مستقلة مشتقة من أطفالها المؤهلين، مع تغطية للأطفال الناقصين؛ لا نسند تلقائيًا إجابة الفرعية مرة أخرى للأب. إذا كان السؤال مرتبطًا مباشرة بالرئيسية دون فرعية فهذا دليل مباشر مستقل وفق سياسة صريحة، ويجب تحديد كيفية دمجه دون ازدواج.

### 10.4 قرار الجاهزية

يُفحص كعقد شروط Versioned Goal Policy: اكتمال محاور حرجة + تغطية + مستوى إتقان موثوق + حداثة + أدلة مستقلة + أداء زمني عند الحاجة + سياق التسهيلات. النتيجة حالة مع `reasons[]`, `missingSkills[]`, `nextAction`, `policyVersion`, `goalVersion`, `evaluatedAt`, `dataRevision`, وليست فقط score من 100. أي أرقام مثل 80% / محاكيين / 21 يومًا تجريبية غير معتمدة حتى معايرة.

### 10.5 رياضيات الاختيار والتحسين

اختيار نشاط `x_a∈{0,1}` تحت هدف متعدد:

`max Σ (EstimatedLearningValue_a - fatiguePenalty_a - planChangePenalty_a) x_a`.

قيود: `Σ minutes_a x_a ≤ availableMinutes`, prerequisite order, time windows, rest days, content entitlement, published resources, student accessibility, independent recheck, school assignment constraints. لا نستخدم الفائدة المتوقعة لادعاء زيادة مضمونة في نتيجة رسمية؛ نعرض خطة ممكنة وبدائل.

للأسئلة: عدد بنود ثابت، تغطية المهارات والأقسام، صعوبة محسوبة/معايرة إن وجدت، عائلات الأسئلة والقطع All-or-None، منع العرض المكثف، وعدم نشر نموذج ناقص. للمدرسة: قيد المعلم/المادة/الفصل/السعة/التوقيت/المدرسة وصلاحية الإسناد. يظل الإقرار والتصحيح والدرجات لمالكها في Go.

## 11. وحدات التنفيذ، دون تضخم في الخدمات

- `taxonomy`: المسار/المادة/شجرة المهارات/العلاقات المعتمدة ومتطلبات سابقة ذات DAG؛ نسخ إصدار السياسة إن كانت بملكية فريق المنهج.
- `questionbank`: السؤال الأصلي ونسخه والتصنيف والتحقق وجودة عناصر البنك و`primary_skill_id`.
- `assessment`: إصدار الاختبار والمحاولات والتصحيح، ونظام اختيار/معاينة الأسئلة المقيد.
- `learning`: `Evidence Qualification`, `Mastery`, `GoalReadiness`, `Recommendations`, `StudyPlan`, `Retention` (حزم داخل الموديول، لا Microservices مفروضة).
- `content`: الروابط الصريحة `topic_skill_links` وأهلية النشر والمحتوى.
- `organizations`: عضويات المدرسة، تكليف المعلمين، سياقات الفصول والمشرفين وتدخلاتهم.
- `reporting`: تجميعات وتقارير مقيدة بالنطاق، مع توضيح المصدر/الفترة/المقام/الأدلة وتطبيق حد خصوصية للمجموعات الصغيرة.
- `notifications`: تذكير بالأعمال المهمة دون إزعاج أو تكرار.
- `operations`: مراقبة التحديثات والبناء والـWorkers والـFeature Flags وسجل التدقيق.
- `ai`: شرح وتلميح اختياري عبر سياق مصرح؛ لا يقرر الدرجات أو الإتقان أو الصلاحيات.

**الأحداث:** `AttemptFinalized` → `EvidenceApplied` → `SkillProgressChanged` → `GoalReadinessRecomputed` → `NextActionPublished` → `PlanAdjusted` → `InterventionReviewed`. يتم التسليم بإشعارات ذات مفاتيح Idempotency وOutbox عند الحاجة، ولا تستبدل الأحداث المتأخرة Decision ذا `dataRevision` أحدث.

## 12. نموذج البيانات الإضافي المقترح — بعد مراجعة الجداول الموجودة

**أقل تغييرات Additive** لا تستنسخ `mastery_evidence`, `skill_progress`, `study_plans`, `school_interventions` أو بنك الأسئلة:

- `learning_goals` + `learning_goal_versions`: scope/owner/type/path/subject/target, policy status, approval and dates.
- `learning_goal_skill_targets`: requirement references leaf skills, weights, critical, qualified evidence type, min independent attempts; لا تربط مجموعات الأمهات والأطفال بطريقة تضاعف المقام.
- `skill_prerequisite_edges`: `from_skill`, `to_skill`, rationale, approval/version; cycle check.
- `learning_readiness_snapshots`: `student_id`, `goal_version_id`, `policy_version`, `data_revision`, `status`, `coverage`, `confidence_summary`, `reason_codes`, `evidence_cutoff`, `updated_at`; يقرأ المستخدم آخر Snapshot صالح فقط.
- `learning_decision_actions`: `student_id`, `goal_id`, `skill_id`, `action_kind`, `resource_ref`, `source_snapshot_id`, `state`, `expires_at`, `reason_codes`.
- تحسين حقول/فهارس أدلة القياس الموجودة لو كانت ناقصة: `attempt_id`, `question_id`, `question_version`, `primary_skill`, `source_kind`, `assistance_level`, `question_family`, `occurred_at`, `event_key UNIQUE`.
- تجميعات قراءة وفق المجال والفترة: `skill_aggregate_snapshots` أو materialized views/SQL read models حسب قياس الحمل، دون إنشاء صف دائم لكل تركيبة فلاتر؛ TTL/refresh/invalidation versioned.
- ربط StudyPlan/Intervention الحالي بالهدف والـDecision والقياس القبلي/البعدي دون جدول منافس.

**قرارات البيانات:** الواجهات تقرأ عقود DTO مصدّرة بواسطة Go، لا جداول مباشرة. جميع الجداول الجديدة بـFK/unique/check وmigration reversible عند الإمكان، واختبارات rollback وbackfill ببيانات معزولة. لا تغيير إنتاجي أو legacy write دون تفويض منفصل.

## 14. ضوابط مكافحة التضخم والأداء والتكلفة

1. لا نسخ السؤال أو الصورة أو دليل الإجابة في بيانات التحليل؛ أحجام الصور والتخزين عبر R2 والمراجع فقط.
2. لا إعادة حساب جميع الطلاب بعد أي محاولة؛ فقط الطالب والمهارات/الأهداف المتأثرة، ثم تحديث تجميعات المدرسة/المنصة بالدفعات؛ Queue + backpressure + retries + dead-letter/reconcile.
3. `PostgreSQL` مصدر الحقيقة، `Redis` Cache/Queue غير سلطوي؛ فهارس مركبة حسب query patterns، `EXPLAIN ANALYZE` واقعي قبل الفهرسة، ومراقبة N+1.
4. فصل hot read models عن event history؛ لا حفظ آلاف Snapshot مكررة بلا retention/expiry. لا حذف للأدلة الضرورية للنتائج والتدقيق دون سياسة موافقة وخصوصية.
5. الـE2E لا يحوّل التحليل إلى آلاف استعلامات؛ cursor/page/time filters؛ تصدير CSV async إذا كبر.
6. ميزانيات CPU/memory/queue زمنية لـWorkers، وTimeout/Cancellation/Cost per plan؛ Go heuristic أولًا، CP-SAT worker لاحقًا عند الحاجة مع تحقق Go لكل قيد ونشر خطة Draft وليس Auto-Approved.
7. AI اختياري مع caching وإذن وtimeout/token budget/fallback؛ التعلم والقياس الأساسي يعملان عند تعطل المزود.
8. `Feature flags` حسب role/path/school/version مع rollback آمن وعدم تغيير تاريخ النتائج.
9. Metrics: `readiness_update_lag`, `decision_stale_rate`, `events_duplication_prevented`, `plan_infeasible_rate`, `optimizer_time_ms`, `query_p95`, `task_queue_depth`, `cost_per_plan`.
10. اختبار حجم realistic (طلاب/محاولات/أدلة/مدارس/مسارات) ومقارنة الموارد قبل وبعد، وPrivacy/PDPL audit.

## 15. صلاحيات وخصوصية يجب اختبارها

- طالب: نفسه فقط؛ مدارس لا تستطيع استرداد تعلمه الذاتي إلا حيث يسمح عقد/سياسة واضحة.
- ولي أمر: الأبناء المرتبطون بعلاقة نشطة فقط؛ يفقد الرابط تزامنًا عند الإلغاء.
- معلم: `school + class + subject` تكليف نشط؛ ليس كامل طلاب المدرسة.
- مشرف: نطاقه المصرح من مدارس وفصول ومصادر؛ لا يكتسب صلاحية من زر UI.
- مدير المدرسة: المدرسة المفوضة، وباقات/وحدات العقد، لا بيانات مدرسة أخرى.
- مالك المنصة: صلاحيات إدارية محددة ومراجعة منظمة للبيانات الشخصية؛ مجمّعات عامة افتراضيًا، لا لوحات تشهير بطلاب أو مدارس.
- المدرب/المؤلف/مراجع المحتوى: عمليات المحتوى ونطاق البنك حسب التكليف لا صلاحية تلقائية على ملفات الطلبة.
- لا منح استحقاق مجاني أو تغيير درجة أو نشر سؤال بواسطة solver أو AI.
- تحليلات المجموعات الصغيرة تخضع لكبت/تجميع للخصوصية؛ تصدير التدقيق لا يكشف معرفات مجهولة أو سجلات حساسة بغير تفويض.

## 16. خطة التنفيذ التابعة للخطة الأصلية

1. **Contract inventory / RED**: جرد واجهات Legacy/Go وschemas/routes/roles وآخر PRs، وإصلاح الفجوات المثبتة في رحلة الاختبار والتقرير مع مراعاة ما دُمج بالفعل في PR #301؛ لا إعادة اختراع مكون موجود. يبدأ التنفيذ من أول فجوة مثبتة في Checkpoint والخطة الواحدة.
2. **G0 taxonomy/goal/version**: مصدر مهارات الهدف كاملًا، primary question skill، صلاحية content links، cycle-check prerequisites، وأنواع الأدلة.
3. **G1 reliable readiness**: تغطية بالمقام الكامل، confidence/recency/counter-evidence، explanations، isolation وidempotency؛ تشغيل shadow computation على عينات قبل الواجهة.
4. **G2 student loop**: بطاقة overview + مسار ذكي + تقاريري + نتيجة + خططي كلها تقرأ Decision واحدًا، من skill diagnosis إلى lesson/practice/reassessment.
5. **G3 parent & school**: رؤية ولي الأمر، التقارير الموحّدة للمعلم والمشرف والمدير، ودورة تدخل واحدة كاملة مع إعادة القياس.
6. **G4 platform intelligence**: aggregations owner dashboard مع مسارات/مواد/مهارات وفجوات المحتوى والبنك والسياسات والإصدارات.
7. **G5 mathematical optimization**: Go deterministic baseline مقابل خطة محسنة، بعد توثيق objective/constraints/benchmarks؛ اختبارات التكوين، scheduler مع CP-SAT منفصل إن أثبتت الحاجة.
8. **G6 calibration & advanced models**: item quality ثم IRT/BKT/knowledge tracing والتنبؤ المُعاير عند توافر بيانات وقبول تربوي، وليس في أول دمج.

تُنفذ دفعات صغيرة مع ownership للملفات ومراجعة مستقلة؛ لا بُنى تنفيذ موازية ولا merges تلقائية. لكل دفعة: Legacy actual UX → HTTP exact payload → Go authorization/domain → PostgreSQL persisted → consumer visible → negative permission tests → screenshot comparison 390/820/1440 → الأربع بوابات Database/Backend/Frontend/Frontend E2E على نفس SHA → review/merge بقرار واضح. تظل حالة المنصة `PARTIAL` حتى دليل الإغلاق.

## 17. معايير قبول صلبة — Golden Cases

- مادة ومسار جديدان من إعداد المدير يعملان دون إضافة switch في Go باسم المسار؛ تحترم الواجهة الترتيب والـRTL والموضوعات.
- 10 مهارات مطلوبة و3 فقط في `SkillProgress`: التغطية تُقاس على 10، ولا تُعلن الجاهزية مع إغفال 7.
- طالب لم يحل أي سؤال: `NEEDS_MEASUREMENT`, لا `WEAK`؛ بنك لا يحوي سؤالًا مؤهلًا: `CONTENT_GAP`, لا لوم الطالب.
- سؤال مرتبط بمهارة فرعية: يسجل مرة واحدة، وتُحسب الرئيسية من أطفالها بلا مضاعفة.
- تكرار webhook/submit أو retry: لا يضاعف الأدلة أو يعيد تقليب قرار أحدث.
- تغيير تصنيف سؤال أو سياسة هدف لا يغير نتيجة محاولة تاريخية؛ يخزن المرجع والإصدار.
- اختبار مماثل أدى الطالب فيه مع مساعد يختلف في أهلية الدليل عن تقييم مستقل؛ لا تُرفع confidence تلقائيًا.
- ربط مباشر بمادة غير منشورة أو محتوى مدفوع: توصية مسموح معاينتها حسب السياسة، وزر الفتح يحترم entitlement.
- ولي أمر يفقد رابط طالب: لا يرى الدليل بعد سحب الرابط، حتى عبر direct API URL.
- معلم خارج مادة تكليفه ومدير مدرسة ثانية: رفض 403/404 بلا كشف تفاصيل.
- المدير يفتح «أضعف 10 مهارات»: النتيجة تذكر العدد الفريد والمقاس وغير المقاس، وليست من اختبارات 5 طلاب مرتبة ظلمًا.
- Go solver يعيد خطة مخالفة قيد أو يتعطل Worker: لا خطة مخالفة تعرض باعتبارها ناجحة؛ يوجد سبب وفشل/بديل.
- «تقاريري» و«المسار الذكي» و«خططي» تفتح مهارة ونطاقًا واحدًا ويرجعان إلى المصدر نفسه ولا يعرضان بيانات مسار سابق أثناء التحميل.
- واجهة الطالب وولي الأمر والمعلم والمشرف ومدير المدرسة ومالك المنصة فعليًا RTL عند 390/820/1440، والخطأ والفراغ والإلغاء والعودة موثقة.
