# P0-C — قراءة تعريف الاختبار المدرسي معزولة بالصلاحيات

**التاريخ:** 2026-10-28 · **الحالة:** تنفيذ شريحة read-only، بانتظار اختبار PostgreSQL الحقيقي في Database CI. **ليست شهادة تكافؤ منشئ الاختبارات كاملًا.**

## الغرض التربوي

بعد أن ينشئ المدير اختبارًا مركزيًا لعدة فصول أو طلاب مختارين، يجب أن يستطيع الرجوع إلى **التعريف المحفوظ فعليًا** (العنوان، المسار، المادة، أسئلة الاختبار بترتيبها ونسخها، زمنه، محاولاته، إعداداته، جمهوره). لا يُقبل افتراض أن ما كان مرئيًا في واجهة الإنشاء حُفظ أو دخل محرك المحاولات.

## العقد المنفّذ في Go

تحت جذر `/api/school-access`:

| الطلب | المعلومات | من يقرأ؟ |
|---|---|---|
| `GET /director/schools/{schoolId}/academic/assessments/{assessmentId}/definition` | تفاصيل حفظ الاختبار + `questionIds` و`questionVersions` + إعدادات/استهداف، دون مفاتيح الإجابات أو بيانات الطلاب | مدير مدرسة نشط لديه `SCHOOL_ASSESSMENTS_MANAGE` وعقد `SCHOOL_ASSESSMENTS` نشط |
| `GET /director/schools/{schoolId}/academic/assessments/{assessmentId}/context` | `id`, `schoolId`, `isPublished` وأعلام الإمكانات | نفس صلاحية الإدارة، وليست صلاحية قراءة التقرير فقط |

- فحصان مستقلان: `application` يرفض المستخدم غير المخول، واستعلام PostgreSQL يعيد فحص عضوية المدرسة والعقد والصلاحية وملكية الاختبار في **عبارة SQL واحدة**. اختبارات مدرسة أخرى/صلاحية مسحوبة تعطي عدم وجود من قاعدة البيانات، دون كشف المدرسة التي يمتلكها الاختبار.
- إعدادات الـboolean تستخدم قيم PostgreSQL الفعلية بما فيها `false` الصريحة؛ لا تتحول إلى قيم افتراضية بسبب frontend. الأسئلة تعرض معرفًا وإصدارًا مثبتًا في `assessment_version_questions`، ولا تعرض تصحيحًا أو صور طالب أو مفاتيح إجابات.
- `Cache-Control: private, no-store`؛ لا نقبل معاملات query غير متوقعة؛ لم تتغير استضافة أو بيانات production.
- جميع اختبارات المدير المنشأة من المسار الحالي منشورة فورًا؛ تعديل المحتوى بعد النشر مقفول كما في Legacy. **Go لم ينفذ بعد clone أو commands**، لذلك `canClone=false`, `canEditContent=false`, `canManageDefinition=false`، حتى لا تكون الواجهة وعدًا غير صحيح. هذا **فرق وظيفي مطلوب إغلاقه** في دفعة لاحقة.
- يحدد `targetScope` هنا **الجمهور الفعلي** من جداول assignment. لا يوجد حقل يحفظ الاسم الأصلي `selected` عند اختيار فصول فقط دون طلاب إضافيين؛ يمكن تمثيل الجمهور نفسه كـ`class/classes`، ويلزم فصل النية النصية عن الجمهور الفعلي لو احتاجت تجربة التحرير المحافظة عليها حرفيًا.

## الاختبارات والمتبقي

1. `go test ./internal/organizations/...` محليًا وتحقق كامل `go test ./...` حيث يسمح loopback، مع RED→GREEN لاختبارات الصلاحيات والـHTTP.
2. `TestDirectorCreateAssessmentPostgres` داخل Database CI على PostgreSQL 18 الحقيقي: نفس الاختبار بعد إنشاء class/classes/selected؛ default settings + false overrides، عقد cross-school، وسحب permission داخل transaction.
3. **التالي قبل نسخ/تعديل اختبارات:** أمر `clone` آمن ينشئ `draft` مستقلًا بدون أي نشر أو تكليف، يحفظ نسخ السؤال الأصلية ويستخدم idempotency، مع منع تعديلات المحتوى المنشور أو الاختبار ذي المحاولات، ثم ربط واجهة الإدارة وإثبات الرحلة بمتصفح جوال/تابلت/مكتب.
4. الاختبار الموحد على مستوى المنصة يظل داخل `internal/assessment`؛ لا يجوز إنشاء محرك تصحيح آخر للمدرسة.

## ما لم نثبته

لا تماثل شامل لمنشئ Legacy؛ لم تُنفذ `compose`, `clone`, `commands` بعد، ولم نثبت إعادة فتح واجهة المدير لهذه البيانات أو تحليل المهارات مطابقًا على مجموعة golden، ولم يحدث ترحيل Mongo→PostgreSQL.
