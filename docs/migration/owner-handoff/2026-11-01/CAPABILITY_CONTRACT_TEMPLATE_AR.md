# قالب فهم ونقل جزئية واحدة

ينسخ داخل سجل الشريحة عند بدء تنفيذ وظيفة. هذا القالب تابع لـplan03 وعقد فهم المنتج؛ تعبئته ليست دليل اكتمال.

## الهوية والملكية

- ID / المهمة القائمة / المسؤول / الملفات المحجوزة:
- SHA الأصل والهدف / branch / PR القائم إن وجد:
- الدور والأدوار المستهلكة / المدرسة والفصل والمسار والمادة:
- حالة الفهم: لم يفحص / مستند إلى وثيقة / مستند إلى كود / أعيد إنتاجه في المتصفح:

## لماذا توجد هذه الجزئية؟

- حاجة الطالب أو الموظف التي تعالجها:
- المدخلات، ومن يملك كل حقيقة:
- قرارها ومخرجاتها، وماذا يحدث بعدها:
- علاقتها ببقية الوظائف، وما يفسد لو اختصرت أو حذفت:
- قواعد المصدر الفعلية وروابط ملفاتها وأسطرها:
- القرارات غير المحسومة أو المتعارضة بين الوثيقة والكود:

## الحالات ومعيار القبول

- تحميل، فراغ، خطأ، صلاحية مرفوضة، مقفل/مجاني/مدفوع، نافذة، تعطيل الزر، Retry مع بقاء المسودة.
- الحفظ ثم قراءة جديدة، reload/deep-link/back/forward، احتفاظ النطاق، تبديل سياق وطلب سابق متأخر.
- أثر التغيير على الدور التالي، وعزل دور/مدرسة/مادة أخرى.
- قواعد النشاط مستقلة: الزمن، التنقل، المحاولات، التغذية الراجعة، التصحيح، إظهار الشرح، وأثر الإتقان. المكون المشترك لا يغير هذه القواعد.
- صور مقترنة للأصل/الجديد بنفس البيانات والدور والحالة والخطوط وDPR عند390/820/1440. اذكر كل فرق بوضوح؛ لا تخفض معيار المقارنة لإخفائه.
