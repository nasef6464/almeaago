**أساس Go:** `nasef6464/almeaago/main@98b0f6d9ad0bba031936d950d087c0bd3d19b7bb`.

## الفجوة المثبتة

عند نجاح `api.forgotPassword(email.trim())`، يعرض Legacy رسالة ثابتة **دون قراءة `response.message`**:

> إذا كان البريد مسجلًا، ستصلك تعليمات الاستعادة. تحقق من البريد الوارد والرسائل غير المرغوب فيها.

في Go كان `ForgotPasswordPage.tsx` يعرض `response.message` أو نصًا احتياطيًا مختلفًا. لذلك أي رسالة نجاح مختلفة من HTTP — أو JSON بلا `message` — تظهر نصًا غير أصلي، وقد تكشف تفاصيل لا يعرضها المصدر.

## الشريحة المنفذة

- الزائر → `/forgot-password` → إدخال البريد → إرسال → `POST /api/v1/auth/forgot-password` → `identity` Go → مستودع الهوية PostgreSQL (لم يُعدَّل) → واجهة النجاح.
- React ينتظر نجاح الطلب، ثم يعرض **النص الثابت نفسه** بغض النظر عن قيمة `message`؛ يظل خطأ HTTP ظاهرًا ويظل البريد محفوظًا عند فشل الإرسال.
- لا تعديل في HTTP/Go/PostgreSQL، ولا RBAC أو CSRF أو الهوية أو النصوص/الأزرار الأخرى. لا مساس بملفات #159/#160/#161/#162/#163/#166/#215/#221.
- اختبار `apps/web/tests/e2e/public-recovery-fixed-confirmation.spec.ts` يحمي ثلاث حالات عند كل من 390/820/1440 RTL: نجاح برسالة خادم مختلفة، نجاح برسالة مفقودة، فشل 503 ثم إعادة المحاولة مع بقاء البريد.
