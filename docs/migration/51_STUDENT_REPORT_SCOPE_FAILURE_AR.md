## الخلل المثبت من الكود
كان effect يضبط `busy` و`error` لكنه يحتفظ بـ`overview` و`results` من النطاق السابق. عند HTTP 503 تعود `busy=false` فيُعرض ملخص ونتائج المسار القديم أسفل خطأ المسار الجديد. هذا انحراف سلامة عرض؛ ليس ادعاء تسرب من قاعدة البيانات. وكذلك عند غياب نطاق مدرسة صالح كانت البيانات السابقة تبقى في state.

## الإصلاح
- مسح `overview` و`results` قبل بدء كل زوج طلبات `GET /api/v1/reports/overview` و`GET /api/v1/reports/results`.
- مسحهما عند فقدان الحساب/الدور/نطاق المدرسة اللازم.
- الاحتفاظ بإلغاء الطلب السابق عبر `AbortController`، وبزر «تحديث» لإعادة المحاولة.
- حذف عبارتين تقنيتين ظاهرتين للطالب (`Reporting API` و`answer keys`) لا تنتميان إلى تجربة Legacy.
- لا تغيير في Go أو PostgreSQL أو scoring أو RBAC أو المدفوعات.

## سلسلة التتبع
طالب → `/reports` → اختيار مسار/مادة/فترة → `reportingClient.overview/results` → `/api/v1/reports/{overview,results}` → Reporting Go (قراءة فقط) → مخزن نتائج/تقدم الطالب → واجهة التقرير. التغيير في عزل state فقط، وليس في سلطة الـAPI أو تخزين البيانات.
