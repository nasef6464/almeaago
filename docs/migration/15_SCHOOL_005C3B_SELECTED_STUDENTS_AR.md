# SCHOOL-005C3B — استهداف فصول وطلاب بأسمائهم في الاختبار المدرسي

تاريخ الدفعة: 2026-10-28. المصدر المرجعي: واجهة إنشاء الاختبار المدرسي القديمة في ALMEAA Node، مع الإضافة المطلوبة لاختبار مركزي يستهدف مجموعة مختارة من الفصول والطلاب. لا تغيير في الواجهة العامة للطلاب أو في صلاحيات نشر الاختبارات خارج المدرسة.

## العقد التشغيلي

- `targetScope=selected`: يرسل المدير `classIds` (صفر إلى 50) و`studentIds` (صفر إلى 200) بشرط وجود فصل أو طالب واحد على الأقل؛ `classId` المفرد فارغ.
- الخادم يوحّد معرّفات UUID، يزيل المكرر ويرتبها قبل حساب بصمة طلب النشر ومعرّف إعادة المحاولة، ويتحقق من مصدر الأسئلة المعتمد.
- تنشأ نسخة الاختبار ونشره للمدرسة فقط. ينفذ التوجيه داخل نفس معاملة PostgreSQL في `assessment_assignment_classes` و`assessment_assignment_users`، ويحسب التقرير الجمهور المستهدف كاتحاد المجموعتين بلا تكرار.
- يجب أن يكون كل فصل نشطًا ويتبع المدرسة المعنية، وكل طالب مسجلاً بعضوية `student` نشطة في **نفس المدرسة** وحساب مستخدم نشط. لا يُقبَل طالب من مدرسة أخرى أو عضو هيئة تدريس أو حساب معطل، حتى لو أرسل العميل المعرّف مباشرة.
- اسم الطالب والفصل فقط يعرضان في منتقي `GET /api/school-access/director/schools/{schoolId}/academic/eligible-students?search=...&page=1&limit=20`. لا البريد أو الهاتف أو بيانات حساسة؛ الاستجابة `private, no-store`، والبحث `%`/`_` حرفي وليس wildcard، والحد الأعلى 50 في الصفحة.
- التحقق من دور مدير المدرسة وصلاحية `SCHOOL_ASSESSMENTS_MANAGE` وتفعيل وحدة `SCHOOL_ASSESSMENTS` يحدث في طبقة الخدمة **ومرة أخرى داخل SQL**، بما يشمل فترة العقد.
- الواجهة تُبقي مجموعة الطلاب المختارين عند الانتقال بين صفحات البحث؛ وتلغي نتائج الطلبات القديمة بعد تبديل المدرسة أو إغلاق نافذة الإنشاء؛ وتتجنب تجاوز العرض في 390 و1440 بكسل.

## اختبارات القبول

| المستوى | الاختبار |
|---|---|
| Application | منع النطاق الخاطئ/القائمة الفارغة/UUID غير الصحيح، وصلاحية المدرسة، وتوحيد المكرر |
| SQL real DB | اختيار جمهور فصل + طالب، وحدة الاختبار، إعادة المحاولة، استبعاد الطالب الخارجي/المعطل/المعلم، وعدم تسريب منتقي الطلاب، وإلغاء الوحدة |
| HTTP | رفض المدرسة الخارجية والصفحة الكبيرة والصلاحية الملغاة، وتأكيد سياسة عدم التخزين |
| Playwright | الانتقال بين صفحات الطلاب، استمرار الاختيارات، إضافة فصل، النشر الصحيح، واستجابة العرض للجوال/الكمبيوتر |

## حالات غير مطلوبة في هذه الدفعة

- لا تعديل للاختبارات المنشورة سابقًا ولا تغيير لبنوك الأسئلة.
- لا منح نشر عام للمعلم أو المشرف؛ مدير المدرسة ينشر ضمن نطاق مدرسته فقط.
- حذف/أرشفة الاختبار، جدولة نوافذ الإتاحة، ومقارنات الفصول بين الاختبارات هي مراحل إدارة وتحليل مستقلة؛ لا تدّعي هذه الدفعة تنفيذها.

## دليل الإغلاق

تُغلق الدفعة بعد نجاح وحدات Go وواجهة TypeScript واختبارات Playwright، ثم نجاح بوابات GitHub **Backend CI / Database CI / Frontend CI / Frontend E2E** على نفس commit. لا يغني اختبار المتصفح الاصطناعي عن اختبار PostgreSQL الفعلي.
