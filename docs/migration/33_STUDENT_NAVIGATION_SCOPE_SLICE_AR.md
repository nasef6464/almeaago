# ALMEAA — شريحة تفضيلات المسارات ونطاق تنقل الطالب

التاريخ: 30 أكتوبر 2026  
الفرع: `feat/student-navigation-scope-20261030`  
المصدر المرجعي للقراءة فقط: `nasef6464/almeaacodax`

## النطاق
إعادة رحلة اختيار الطالب للمسار والمرحلة: يكتشف الكتالوج، يختار مسارًا ومرحلة عند الحاجة، يحفظ الخادم الاختيار، ثم يطبق الهيدر نطاق المسار والمرحلة نفسها. شريط الاختيار لا يظهر لغير الطالب.

## ملكية البيانات والأمان
- Learning navigation يملك `enrolledPaths` و`pathStageSelections` كتفضيلات عرض فقط.
- هوية المستخدم تؤخذ من جلسة Go، ولا يقبل API معرّف actor من العميل.
- PATCH يتطلب CSRF ويفحص المرحلة التابعة للمسار.
- PostgreSQL يحفظ علاقات FK داخل معاملة واحدة، ويقفل صف المستخدم لتسلسل الكتابات المتزامنة، ويكتب audit في المعاملة نفسها.
- فشل التدقيق يلغي التعديل. التفضيل لا يمنح اشتراكًا أو استحقاقًا مدفوعًا أو أهلية اختبار ولا يغير التصحيح أو النتائج.

## التغييرات
- Provider وسياق نطاق الطالب، شريط اختيار المسار/المرحلة وحوار التسجيل.
- Go module مستقل في `internal/learning/navigation`، وواجهة GET/PATCH، وmigration `000046`.
- ربط API في خادم Go، واستخدام النطاق نفسه في شجرة الهيدر.
- اختبارات provider/scope وPlaywright، واختبار HTTP/PostgreSQL حقيقي في مخطط معزول.

## أدلة القبول
- Backend CI وFrontend CI وDatabase CI وFrontend E2E يجب أن تنجح على SHA واحد.
- PostgreSQL integration يثبت حفظ/إعادة قراءة HTTP وعزل المستخدم ورفض مرحلة من مسار آخر وrollback عند فشل audit.
- E2E يستخدم API fixtures لإثبات تفاعل الواجهة؛ ليس اختبارًا بصريًا حيًا مع Go.
- لا صور Legacy↔Go حية في هذه الشريحة؛ لا تستخدمها كشهادة تطابق بصري للهيدر.

## الحدود
- **PARTIAL:** كتالوج taxonomy الحالي مصدر المسارات/المراحل؛ إرجاع `showInNavbar` وبيانات العرض الكاملة للأدوار المختلفة يحتاج إثباتًا مستقلًا.
- **NOT PROVEN:** تطابق الهيدر الكامل، البحث/الثيم/السلة/الإشعارات/الحساب، وجهات `/mock-exams` و`/pricing` و`/blog` وتبويب الباقات، وصور المقارنة الحية على 390/820/1440.
- لا نشر ولا تعديل للمصدر القديم ولا بيانات إنتاج.
