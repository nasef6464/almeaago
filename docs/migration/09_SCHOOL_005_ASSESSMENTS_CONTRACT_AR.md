## 1. ما الذي يعده المستخدم «اختبارات المدرسة»؟

المسار الظاهر لمدير المدرسة هو تبويب `assessments`، وعنوانه «اختبارات المدرسة»، ضمن «التعلم والمتابعة». لا يظهر إلا عند اجتماع `SCHOOL_ASSESSMENTS_MANAGE` مع الوحدة `SCHOOL_ASSESSMENTS` في **المدرسة المختارة**. يُفصل عن اختبار المعلم المنشور لفصله وعن بنك/اختبارات مدير المنصة.

| العملية في Node | الملف/العقد المرجعي | ما يجب نقله/التحقق منه في Go |
| --- | --- | --- |
| عرض أحدث الاختبارات وعددها | `SchoolDirectorAcademicCenter.tsx`، `GET /school-access/director/schools/:schoolId/academic/assessments` | قائمة نطاقية + العدد كما في الاستجابة؛ حد القائمة في Node حاليًا 100 مرتبة بالأحدث |
| إنشاء اختبار للفصل أو للمدرسة كاملة | `DirectorCatalogFields.tsx`، `DirectorQuestionPicker.tsx`، `POST .../academic/assessments` | عنوان + مسار + مادة + أسئلة **معتمدة** + هدف `class/school`؛ نجاح 201؛ سياسة النشر المباشر للهدف |
| فتح «النتائج والإدارة» | `DirectorAssessmentCards.tsx`، `GET /school-assessments/:id/context?schoolId=...` | التفويض لكل اختبار بعد فحص جمهور الاستهداف، لا بالاكتفاء بصلاحية المدرسة |
| النتائج والمتغيبون والتحليل | `SchoolAssessmentReportWorkspace` وعائلة `schoolAssessmentsRouter.ts` | سجل محاولات الطلاب الحقيقي ونسبة الإكمال والتحليل، مع عدم خلط مستهدفين من مدارس أخرى |
| تعديل التعريف والنشر/الإخفاء | `DirectorAssessmentCards.tsx`، `/school-assessments/:id/definition` ومسار تحديثه | منع تعديل محتوى منشور أو ذي محاولات، نسخة جديدة عند الحاجة؛ concurrency/revision |
| استنساخ اختبار وإعادة استهدافه | `/school-assessments/:id/clone`، محرر `UnifiedQuizBuilder` | نسخة بصلاحيات مُعاد احتسابها، بلا نقل محاولات ولا كشف جمهور غير مفوض |
| تذكير الغائبين وإعادة فتح الموعد | `/school-assessments/:id/commands` | command identity/idempotency وسجل تدقيق وحصر المستهدفين والتحقق من نافذة الموعد |

**التسلسل الحقيقي:** مستخدم ← تبويب مدير المدرسة ← كتالوج المسار/المادة ← منتقي أسئلة بنك معتمد ← إنشاء لاختبار الفصل/المدرسة ← عرض نتائج ← أوامر الإدارة. القائمة وحدها لا تغلق هذا التبويب.

## 2. حقائق المصدر التي لا يجوز تبسيطها

1. `schoolAssessmentAudience` في Node يطابق **استهداف المدرسة بالكامل أو أحد فصولها أو طالبًا من طلابها**؛ لا يكفي `ownerId` لإظهار كل الاختبارات. توجد حالة إضافية لمسودات المدرسة المركزية غير المنشورة والخالية من المستهدفين.
2. الطلب ينتمي إلى مدرسة محددة حتى لو كان المدير مخولًا في أكثر من مدرسة؛ نقل السياق أ→ب→أ يجب أن يبطل نتائج القراءة والحوار والأمر القديم.
3. اختيار «المدرسة بالكامل — اختبار مركزي» يرسل `targetScope: 'school'` و`classId: ''`، ولا يصح تفسير قيمة `schoolId` على أنها `classId`.
4. الإنشاء يختار أسئلة `approvalStatus: approved`، يتحقق من المسار، ويجمع `skillIds`. مراجع السؤال لا تُنسخ من البنك، ولا تُقبل أسئلة غير معتمدة أو مكررة.
5. صلاحية قائمة الاختبارات تختلف عن صلاحيات إدارة اختبار **بعينه**؛ `schoolAssessmentManagementPolicy.ts` يعيد حساب `canManage`, `canClone`, `canEditContent` والجمهور قبل الأوامر.
6. النشر في المصدر يُظهر الاختبار لمستهدفيه، ولا يضيفه للاختبارات العامة (`showOnPlatform: false`).
7. مؤشّر `schoolAssessments` في ملخص المدير يتناول المنشور المستهدف في المدرسة، وقد يشمل تقييمًا منشأ خارج إدارة المدرسة؛ قائمة الإدارة ليست بالضرورة نفس مجموعة المؤشر.

## 3. خريطة PostgreSQL الحالية والفجوات المثبتة

| مفهوم Node | الموجود في Go/PG | القرار/الفجوة |
| --- | --- | --- |
| `Quiz` وتاريخ النشر | `assessments`, `assessment_versions`, `workflow_status`, `published_version` | الدومين موجود لكن لا يسمح حاليًا بدور `school_admin` في خدمة الكتابة العامة |
| `questionIds` المعتمدة | `questions`, `question_versions`, `assessment_version_questions` | `validateRefs` الحالي يتحقق من أن السؤال غير مؤرشف، **وليس أن workflow_status = approved**؛ يجب فرض شرط المصدر في أمر إنشاء المدرسة |
| `targetGroupIds=[schoolId/classId]` | `assessment_assignments.school_id`, `assessment_assignment_classes` + migration `000042` | أُضيف `targets_entire_school` المنفصل؛ قائمة المدير لا تعتبر `school_id` وحده استهدافًا، واختبار PostgreSQL على CI هو بوابة التحقق |
| `targetUserIds` | `assessment_assignment_users` | قائمة/تقرير مدير المدرسة لا تعرض طالبًا خارج عضويته الصحيحة ولو استُهدف بمعرف مباشر |
| قفل المحتوى بعد النشر/المحاولات | `assessment_attempts`, `assessment_results`, version/revision | يلزم خدمة سياق وإذن مخصصة لإعادة استخدام API المدرسة، لا فتح محرر المنصة خامًا |
| مسار/مادة وأسئلة | `paths`, `subjects`, `questions` والعلاقات | تحقق server-side من التطابق الحقيقي والتصريح، وليس مجرد select في React |
| التذكير/إعادة الفتح | خدمات assignment/session الحالية | يلزم mapping أوامر هوية وتدقيق وتوقيت مستقل؛ **لم يُثبت تكافؤها بعد** |
| مسودة اختبار مركزي بلا مستهدفين | `assessments.is_school_central_draft` في migration `000042` | التمثيل صريح، والقيمة الافتراضية false؛ يجب تعيينها أثناء إنشاء أو استيراد المسودة فقط بعد التحقق من `mode: central` في المصدر |

**قرار هندسي أولي:** الاحتفاظ بواجهة React القديمة قدر الإمكان والهوية/الألوان/التسميات، مع خدمة `SchoolDirectorAssessment` في Go تُستخدم من مسارات `/api/school-access/director/...`، وتستدعي primitives الدومين الموجود بدل تكرار قواعد التصحيح/الدرجات. أي تغيير مخطط PostgreSQL يظل migration إصدار جديد additive مع فحوص rollback، لا إعادة كتابة بيانات المستخدم.

## 4. التنفيذ بدفعات وبوابات إغلاق كل دفعة

### SCHOOL-005A — إظهار القائمة ونطاقها

- اختبار سلبي أولًا: دور آخر أو مدرسة بلا إذن/وحدة → `403`؛ مدير أ لا يرى مسودات خاصة بمدرسة ب؛ المستخدم المستهدف مباشرة من خارج المدرسة لا يدخل القائمة؛ UUID غير صالح → `4xx`.
- التنفيذ الحالي: `GET /api/school-access/director/schools/{schoolId}/academic/assessments` مفوض بالخادم، وبطاقات قراءة فقط دون أزرار تحرير/نتائج شكلية؛ `dueDate` غير مضمن مؤقتًا لأن PostgreSQL يدعم أكثر من موعد لنفس الاختبار.
- تثبيت Query يدمج استهداف المدرسة والفصول والأفراد، ومسودات المدرسة الخالصة، مع `DISTINCT` و`ORDER BY created_at DESC` وحد Node. اختبارات PostgreSQL ضد **المخطط الحقيقي المهاجر** وليس mock schema.
- إظهار القائمة والعدد في تبويب مع شرط صلاحية، حفظ ترتيب الأقسام، وعدم إرسال طلب بلا إذن. Playwright للتبديل المتأخر وأحجام 360–1920px.

### SCHOOL-005B — الإنشاء من السؤال المعتمد

- RED→GREEN: لا إنشاء بلا عنوان/مسار/مادة/سؤال، ولا سؤال غير معتمد/خارجي، ولا فصل من مدرسة أخرى، ولا تكرار بالنشر مرتين/انقطاع الشبكة.
- معاملة واحدة تكتب تعريف الاختبار وإصداره وأسئلته ونشره واستهدافه وتدقيقه؛ تراجع بالكامل عند الإخفاق؛ جمهور المدرسة صريح في البيانات.
- منتقي أسئلة مربوط بالبنك المُعتمد نفسه مع دعم الصور والجذور والكسور/الأشكال وخيارات الإجابة؛ التحقق من العرض للموبايل/التابلت/الكمبيوتر.

### SCHOOL-005C — الإدارة والنتائج والأوامر

- سياق إذن لكل اختبار؛ مقارنة جمهور الاختبار مع عضوية المدرسة وفصولها؛ `canEditContent` مقفل عند النشر أو وجود محاولات حسب المصدر.
- تقارير الطالب والمهارة والغياب؛ استنساخ/نشر/إخفاء؛ تذكير وإعادة فتح. كل أمر سجل تدقيق، idempotency حيث يلزم، ورفض سلطة المدرسة الأخرى.
- اختبارات E2E للنتائج الفعلية (صفر/طالب لم يدخل/دخل/أعاد)، عدم تكرار المبلغين، ومنع كشف بيانات ب في سياق أ.

### SCHOOL-005D — الاعتماد المقارن

- Frontend, Backend, Database, Playwright على SHA واحد؛ عقد HTTP + SQL حتمي + responsive (360,390,430,768,1024,1366,1440,1920).
- لقطات مرجعية Node وGo **بنفس fixture والحالة**، قياس الحدود والمسافات والسلوك على اللمس. لا `PARITY_PROVEN` قبل المقارنة والإثبات.
- ترحيل Mongo→PostgreSQL لاحقًا بدفعة منفصلة مع mapping للمعرفات والعلاقات وcounts، dry-run ثم reconciliation؛ لا اتصال إنتاجي ولا حذف بيانات في هذه المرحلة.

## 5. حالات «لا تفعل»

- لا تعرض رابط `assessments` لمجرد وجود جدول assessments؛ لا تُنشئ أزرار تقارير أو تحرير غير مدعومة.
- لا تجعل `owner_school_id` وحده مصدر قائمة الاختبارات؛ لا تجعل `assignment.school_id` بمفرده دليل استهداف كل طلاب المدرسة.
- لا تستخدم `role: school_admin` بلا صلاحية المدرسة ووحدة عقدها؛ لا تقبل schoolId من JSON كدليل سلطة.
- لا تعلّم السؤال أو الاختبار أنه «معتمد» للتحايل على نقص صلاحية أو على سياسة مراجعة البنك.
- لا تعدّ نجاح بناء React إثباتًا للتكافؤ مع Node، ولا تغيّر خادم Node/بيانات الإنتاج.
