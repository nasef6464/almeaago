# SCHOOL-003 — تكليفات المعلم الحالية وإيقاف التكليف

**تاريخ التحليل:** 2026-10-27  
**المصدر المرجعي:** `almeaacodax/dashboards/school-director/DirectorTeacherAssignments.tsx` و`SchoolDirectorDelegatedOperations.tsx`  
**هدف Go:** `apps/web/src/features/organizations/pages/SchoolDirectorDashboardPage.tsx`  
**الحالة:** LOCAL IMPLEMENTATION & FULL E2E VERIFIED / REMOTE CI & FINAL REVIEW PENDING

## عقد السلوك المنقول من Node

1. تعرض شاشة مدير المدرسة قائمة التكليفات النشطة **للمعلم المختار** فقط، لا جميع معلمي المدرسة.
2. كل صف يظهر **اسم الفصل واسم المادة**؛ إن كانت المادة `NULL`/فارغة تاريخيًا يُعرض «مادة غير محددة»، وإن غاب اسمها من الكتالوج «مادة مسجلة».
3. يظهر التحذير عندما يوجد أي تكليف فعال بلا مادة أو أكثر من مادة مختلفة للمعلم المختار. الإيقاف متاح للسجل المخالف، ولا يُحذف السجل التاريخي.
4. يرسل «إيقاف التكليف» `teacherId` و`classId` و`subjectId` الأصليين مع `status: inactive` وCSRF إلى نطاق `/api/school-access/director/schools/{schoolId}/assignments`؛ لا يحتاج العميل `assignmentId` لاتخاذ قرار الاستهداف لأن عقد API يعتمد الثلاثية.
5. تعاد قراءة تكليفات المدرسة بعد نجاح العملية، وتظهر رسالة إتمام. أثناء الطلب تتعطل أزرار الإيقاف منعًا للتكرار.
6. لا تظهر شاشة التحكم دون `SCHOOL_TEACHERS_ASSIGN` و`SCHOOL_CORE`، وتستخدم مكونات متجاوبة على الهاتف والتابلت والكمبيوتر.

## تحقق طبقة Go الحالية

- `legacyAssignmentStatus("inactive")` يعيد `AssignmentStatusEnded`، ويعرض `presentLegacyAssignment` حالات `ended/revoked` على الواجهة باسم `inactive`.
- `UpsertAssignment` يتحقق من دور المدير أو صلاحية المدرسة المحددة؛ مستودع PostgreSQL يحدث سجل المطابقة `school_id + teacher_id + class_id + subject_id` في المعاملة ويحتفظ بتاريخ الإنشاء.
- يجب التعامل مع `subjectId: ''` التاريخي عند الإيقاف؛ رفض المادة الفارغة يخص إنشاء تكليف **نشط** فقط.

## معايير الاختبار والبوابات

- Playwright E2E: اختيار المعلم، ظهور الفصول والمواد، إخفاء حالات inactive، تحذير المادة التاريخية الفارغة، إرسال `inactive` مع CSRF ونطاق المدرسة، تحديث القائمة فور الاستجابة.
- صلاحيات: لا قائمة عند فقد الصلاحية/الوحدة.
- API: لا تعديل لمدرسة أخرى؛ اختبار 403/404 ونطاق العقد موجود جزئيًا في اختبارات التطبيق، ويحتاج تغطية مسار الإيقاف تحديدًا.
- تجربة سياق المدرسة: تمنع أرقام أجيال القراءة والزيارات (`loadEpoch` / `schoolVisitEpoch` / `teacherReadVersion`) إعادة بيانات أو رسائل مدرسة سابقة، بما في ذلك مسار «أ→ب→أ» وتداخل قراءة كشف المدرسة مع إيقاف تكليف. تغطية السباقات ليست بديلًا عن مراجعة كل عملية جديدة مستقبلًا.
- Gate: Backend, Frontend, Database, Frontend E2E على رأس الفرع نفسه، ولا دمج مع فحص أحمر.

## قرار التنفيذ

نستبقي `/api/school-access` لتوافق الواجهة مع نسخة Node، ونستخدم مكون قائمة صغيرًا مستقلًا مع callback للإيقاف في لوحة المدير. لا migration لقاعدة البيانات، ولا استبدال لواجهة المدير التي بُنيت سابقًا؛ الإضافة على العقد المرئي الحالي فقط.

## سجل اختبار هذه الدفعة

- كتبت اختبار Playwright لظهور تكليفات المعلم وإيقاف تكليف محدد. **RED:** فشل لأن المنطقة `تكليفات المعلم الحالية` غير موجودة. ثم **GREEN:** نجح بعد إضافة `DirectorTeacherAssignments` وربطه بمعاملة `inactive`.
- كتبت اختبارًا إضافيًا يعلّق رد المدرسة الأولى ثم يبدل إلى المدرسة الثانية. **RED:** ظهر طالب المدرسة الأولى بعد وصول الرد القديم. ثم **GREEN:** نجح بعد إضافة epoch للطلبات وتصفير اختيار المعلم والطلاب والتكليفات عند تبديل المدرسة.
- اختبار ثالث لمعاملة «إنشاء طالب» تبدأ في المدرسة الأولى وتكتمل بعد الانتقال للثانية: **RED:** `refresh` المستدعى من closure القديمة أعاد طالب المدرسة الأولى؛ **GREEN:** حفظ `activeSchoolId` ومقارنته قبل تحديث الحالة وقبل إعادة التحميل، مع منع رسائل نجاح الطلب القديم من الظهور في المدرسة الجديدة.
- اختبار رابع لحقل كلمة مرور طالب جديد عند تبديل المدرسة: **RED:** بقي النموذج مفتوحًا في المدرسة الثانية رغم عدم وجود صلاحية إضافة؛ **GREEN:** تُغلق نماذج الإضافة/التعديل وتُصفّر كلمات المرور وأسماء الفصول وحقول التكليف عند تبديل المدرسة.
- اختبار خامس لإيقاف تكليف بدأ في المدرسة الأولى واكتمل بعد دخول مدرسة ثانية لها معلمون مختلفون: **RED:** استبدلت استجابة المدرسة الأولى قائمة معلمي المدرسة الثانية؛ **GREEN:** توحيد إعادة قراءة المعلمين عبر `reloadTeachersForSchool` مع مقارنة نطاق المدرسة قبل وبعد الطلب، واستخدامه للحفظ والإيقاف.
- مراجعة مستقلة كشفت مسارات أخرى قد تكتب حالة المدرسة السابقة: **RED→GREEN** لنقل طالب متأخر بعد تبديل المدرسة؛ أضيفت حراسة المدرسة والزيارة قبل تحديث الطالب أو إظهار الرسالة، وعُممت على تعديل الطالب، تعطيله، وإنشاء/تعديل الفصول.
- **RED→GREEN** لتزامن قراءة كشف الطلاب مع إيقاف تكليف المعلم: كانت نتيجة القراءة القديمة تعيد التكليف الموقوف إلى قائمة النشطين؛ أصبح تحديث المعلمين محكومًا بإصدار مستقل عن تحديث الطلاب.
- **RED→GREEN** لمسار «المدرسة أ → ب → أ»: كان شرط معرف المدرسة وحده يسمح لطلب من زيارة أ القديمة بالتأثير في الزيارة الجديدة؛ `schoolVisitEpoch` يمنع ذلك.
- **RED→GREEN** لإضافة طالب تكتمل ثم تنتظر تحديث الكشف: كان إشعار نجاح الإضافة يظهر بعد الانتقال إلى مدرسة أخرى؛ أُعيد التحقق من معرف المدرسة ورقم الزيارة **بعد** انتظار إعادة التحميل.
- تكرار استقرار الاختبار الأصلي لتبديل المدرسة: حدث فشل ظهور أول طالب مرة واحدة أثناء سلسلة محلية، ثم اجتاز السيناريو منفردًا و`--repeat-each=5` (5/5) ومجموعة مدير المدرسة (10/10). **تُراقب هذه القابلية للتذبذب في CI؛ نجاح الإعادة وحده ليس إثبات إزالة السبب.**
- نجح `npm run build`، شاملاً `tsc -b`، على الرأس المحلي بعد آخر مراجعة. نجحت **14/14** اختبارات لوحة مدير المدرسة و**95/95** اختبار Playwright للواجهة كلها محليًا بعد الإصلاحات؛ ويظل CI للرأس المنشور شرطًا للدمج. تحذير حجم حزمة JavaScript (~987KB) تحذير أداء غير مانع، ويحتاج معالجة منفصلة بقياس تحميل فعلي.
