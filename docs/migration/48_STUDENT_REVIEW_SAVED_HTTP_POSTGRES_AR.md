## عقد الرحلة
طالب -> نتيجة/مكتبة مراجعة -> PUT `/api/v1/review/questions/:id/saved` -> `learning/application.Service.SetSaved` -> `learning/repository/postgres.Repository.SetSavedReview` -> `review_cards` و`review_card_skills` -> GET `/api/v1/review/library?tab=saved&pathId=...&subjectId=...` -> عرض البطاقة في واجهة المراجعة القائمة.

الأصل يُبقي بطاقة واحدة لكل طالب/سؤال؛ الإلغاء يحذف بطاقة `saved_review` اليدوية التي ليس لها خطأ، ويبقي بطاقة الخطأ/الإتقان ويزيل علم الحفظ فقط. Go يستخدم `updated_at` كرمز تفاؤلي في إجابة المراجعة؛ إعادة PUT/DELETE دون تغير منطقي لا يجب أن تبطل هذا الرمز.

## الفجوات المثبتة
1. **RED مثبت PostgreSQL:** `SetSavedReview` القديم يحدث `updated_at` عند إعادة PUT لسؤال محفوظ بالفعل. فشل الاختبار الحقيقي `TestReviewSavedHTTPPostgres` مع اختلاف الرمز الزمني؛ تشغيل GitHub https://github.com/nasef6464/almeaago/actions/runs/40913703429. لا يُعد فشل gofmt في بوابة Backend إثباتًا لهذا العيب.
2. **علاقة SQL:** إلغاء بطاقة `saved_review` بحقل مهارة مرتبط يحاول حذف `review_cards` مباشرة بينما `review_card_skills.review_card_id` مفتاح أجنبي `ON DELETE RESTRICT`. لا يكتمل الإلغاء قبل حذف الروابط التابعة داخل معاملة.
3. **تسابق:** قراءة نوع البطاقة دون قفل ثم حذفها قد تتسابق مع ترقية البطاقة إلى دليل خطأ/إتقان. الاختبار الجديد يحجز السطر ثم يحاكي تحديث الدليل قبل الإلغاء.

## التنفيذ
- PUT يحدث `saved_for_review/saved_at/updated_at` فقط عند تغير حالة الحفظ؛ عند إعادة الطلب يميز وجود البطاقة من عدمه ويحافظ على 404 للسؤال غير الموجود في ذاكرة الطالب.
- DELETE داخل معاملة PostgreSQL مع `SELECT ... FOR UPDATE`. البطاقة اليدوية دون خطأ: حذف روابط المهارات أولًا ثم البطاقة؛ البطاقة ذات دليل: إبقاؤها وإزالة الحفظ فقط؛ إعادة DELETE لا تحدث `updated_at`.
- اختبارات HTTP مع CSRF والدور والطالب الآخر وقراءة المكتبة بعد إعادة إنشاء الـhandler، واختبار FK حقيقي في schema معزول، وتزامن كاتبين على البطاقة نفسها.
- لا تغيير scoring أو RBAC أو جداول الإنتاج أو واجهات الفرق الأخرى أو أي عناصر مرئية.
