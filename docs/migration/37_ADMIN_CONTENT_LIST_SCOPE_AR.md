## نطاق الرحلة وعقد القبول

المسؤول يفتح «إدارة المحتوى التعليمي»، يعرض دورات مسار، ينتقل إلى الدروس أو المكتبة أو مسار آخر، وينتظر طلب HTTP أو يواجه فشلًا. يجب ألا تظهر صفوف أو عدادات من نطاق سابق داخل النطاق الحالي، ولا أن تظل إجراءات التعديل/النشر مرتبطة بصف سابق. يستمر استخدام Go الحالي للقراءة المقيدة بالمسار/المادة والحالة، وPostgreSQL هو مصدر الحقيقة؛ لا تغيير في عقد API أو RBAC أو محرك التصحيح.

المصدر `dashboards/admin/CoursesManager.tsx` يعرض قائمة دورات مع مرشحات المسار والمادة والحالة. النسخة المستهدفة `ContentAdminPage.tsx` تجمع قوائم الدورات والدروس والتأسيس والمكتبة في تبويبات منفصلة؛ هذه الدفعة **لا تصدّق تطابق تصميمها أو تقسيمها مع الأصل**. الفجوة المثبتة هنا من الكود المستهدف: `rows` و`hasMore` وعدادات `stats` كانت تحمل نتيجة الطلب السابق حتى تصل استجابة الطلب الجديد. شرط `loading` أخفى الجدول أثناء التحميل لكنه لم يعزل العدادات، ولم تفحص `then` إلغاء الطلب قبل قبول الاستجابة.

## التنفيذ

- حفظ مفتاح نطاق دقيق لكل قراءة: `tab/page/pathId/subjectId/debouncedSearch/workflowStatus/reloadKey`، مع معاملة `workflowStatus` كفارغ في التأسيس.
- عرض الصفوف والعدادات والتنقل بين الصفحات **فقط** عندما يتطابق نطاق الاستجابة مع النطاق الحالي، حتى في الإطار الأول قبل تشغيل `useEffect`.
- إفراغ الصفوف و`hasMore` عند بدء القراءة وعند فشلها، وتسجيل النطاق بعد النجاح أو الفشل، مع رفض الاستجابات المتأخرة بعد `AbortController.abort()`.
- منع استجابة التصنيف المتأخرة من تغيير `taxonomy` بعد إلغاء الطلب.
- عدم إضافة أي زر أو قسم أو بطاقة جديدة، وعدم تغيير API أو Go أو SQL. إعادة استخدام `contentClient` و`ListCourses/ListLessons/ListLibraryItems/ListTopics` ومرشحات Go/PostgreSQL القائمة.

## اختبارات RED → GREEN

أضيفت اختبارات Playwright في `apps/web/tests/e2e/admin-content-list-scope.spec.ts` لحالات:
1. تغيير الدورات → الدروس مع طلب درس بطيء.
2. تغيير الدورات → المكتبة مع HTTP 503.
3. تغيير مسار الدورات مع طلب بطيء لمسار آخر.

كل حالة عند 390/820/1440 بكسل (9 اختبارات). تبدأ الدفعة باختبارات RED في commit `b85cc714371036fb058d070914573658496666b5`، ثم إصلاح الواجهة في commit `50b74098e2e5856df41d8435e74cf08b9ed7f96a`. نتيجة CI يجب تسجيلها من التشغيل الفعلي، لا افتراض نجاحها. اختبار المتصفح يستخدم HTTP محاكى؛ لا يثبت تكامل جلسة حقيقية مع Go/PostgreSQL.

## أثر الرحلة عبر الطبقات

`Admin/Teacher → ContentAdminPage filters/tabs → GET /api/v1/{courses|lessons|library|foundation/topics}?pathId&subjectId&... → content HTTP handler → application list authorization → PostgreSQL repository query → filtered list consumer`.

لم يتغير عقد HTTP أو خدمة Go أو SQL، ولذلك يبقى اختبار PostgreSQL المباشر لنطاق هذه الدفعة **PARTIAL** إلى أن يُثبت ببيئة معزولة. الإذن الخادمي مستقل عن إخفاء عناصر الواجهة.
