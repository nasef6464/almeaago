## الفجوة المثبتة (وليست مجرد فرضية)

`internal/content/repository/postgres/helpers.go::validateTopicParentTx` كان يفحص وجود الأب ونطاقه ويستخدم `WITH RECURSIVE` لمنع دورات الشجرة، لكنه لم ينسق المعاملات المتزامنة. يمكن لمديرين تعديل موضوعين مستقلين في المادة نفسها في الوقت نفسه:

1. طلب A يختار B أبًا، وطلب B يختار A أبًا.
2. كل معاملة ترى الشجرة القديمة قبل اعتماد الأخرى، فتجتاز فحص الدورات.
3. كلا التعديلين ينجح، وتصبح شجرة `foundation_topics` دورية.

**دليل RED تشغيلي على PostgreSQL 18:** [Content Foundation Parent Cycle CI #40947968421](https://github.com/nasef6464/almeaago/actions/runs/40947968421) على `b2dbabf3fd2306d79bdefa043b95c76ec8284be7`. فشل الاختبار الجديد ثلاث مرات بالرسالة `concurrent reciprocal reparent must be rejected, got <nil>`. نجاح فحوص النطاق والأب المؤرشف داخل الاختبار نفسه يميز السبب عن أخطاء الإعداد.

## الإصلاح

استعملنا `pg_advisory_xact_lock` بمفتاح ثابت للموديول ومفتاح نطاق `pathID:subjectID` **داخل نفس معاملة PostgreSQL** وقبل قراءة شجرة الآباء. بذلك لا تستطيع عمليتا إعادة ربط الأب في المادة نفسها اجتياز التحقق في وقت واحد؛ الثانية ترى التعديل المعتمد أو تنتظر rollback، ثم تستعيد قاعدة الرفض `content.ErrConflict` إذا نشأت دورة.

- لا نضيف عمودًا ولا نغير هوية `topicID` أو ارتباطاته بالمهارات أو مسارات الطالب.
- التعديلات لمواد مختلفة لا تحتاج إلى قفل واحد (تصادمات hash النادرة تؤدي إلى انتظار زائد لا إلى تجاوز تحقق).
- فحص self-parent والأب المؤرشف ونطاق المادة كما هو.
- يستمر قفل المعاملة حتى `Commit` أو `Rollback`؛ لا توجد سلطة جديدة في الواجهة.

**دليل GREEN:** [Content Foundation Parent Cycle CI #40948234947](https://github.com/nasef6464/almeaago/actions/runs/40948234947) على `fb34b291606f7f19941e86ffb0b5a79d5946ca37`، نجحت الحالات الثلاث `-count=3` باستخدام PostgreSQL 18 معزول. بعد هذا التشغيل أضيف تأكيد SQL لاسترجاع الأب المحفوظ ورفض الأب المقابل، وسيُعاد التحقق منه على SHA النهائي.

## عقد الرحلة بين المدير والطالب

| الطبقة | المسار | الحالة |
|---|---|---|
| المدير / UI | تحرير أب موضوع التأسيس، والحفظ، والفشل، والرجوع | PARTIAL — لم نغير واجهة #160 ولا نزعم اختبار المتصفح |
| HTTP | `PUT /api/v1/foundation/topics/{id}` → `updateTopic` | VERIFIED من تسجيل route والكود، لا اختبار HTTP جديد |
| Go | `Service.UpdateTopic` → `Repository.UpdateTopic` | VERIFIED من تتبع الكود؛ لا تغيير سياسة أو صلاحيات |
| PostgreSQL | `validateTopicParentTx` → `foundation_topics` داخل المعاملة | VERIFIED في RED→GREEN PostgreSQL |
| الطالب | `GetLearnerTopic` وقراءة الارتباطات بنفس `topicID` | PARTIAL — عقد بلا تغيير في API، E2E حقيقي غير منفذ |

**عقد تنسيق مالك الطالب:** لا تتغير حقول الاستجابة أو ترتيب أزرار «فيديو / تدريب / ملف الدعم» ولا تشغيل الفيديو. فشل إعادة ربط أب دوري يجب أن يرجع خطأ تعارض، لا بيانات شجرة دورية؛ إعادة المحاولة بعد تحديث الشجرة تحتاج مراجعة مدير واضحة، ولا يجوز افتراض نجاح الحفظ.
