## الفجوة والإصلاح

مرجع المصدر: `components/Header.tsx`، البصمة `c4e45e5d9bd485538036e98f70eac42471a8fa71`. الأصل يعرض الصورة الدائرية بجانب الاسم دائمًا. Go كان يختار الصورة أو النص؛ لذلك أخفى حفظ الشعار اسم المنصة، واستخدم مقاسات مختلفة للصورة.

أُعيدت الدائرة بمقاسي36/44px وحدودها الأصلية، مع بقاء الاسم والعبارة التكميلية، ولون الاسم في الوضع الداكن والنص البديل الأصلي. أُعيد استخدام محرر #155 وخدمة #154 والجلسات والصلاحيات والتخزين القائمة. لا دومين أو API أو مخطط تخزين جديد. أُدرج #155 المدمج عند `06b7db7fe7493cd90ee79989a1cb1c890f9769df`.

## الاختبارات والمراجعة

- اختبار عرض فعلي للمكون: حالتا الزائر والطالب فشلتا قبل الإصلاح ثم نجحتا، وحالة الشعار الفارغ ناجحة؛ 3 اختبارات للشعار و7 مع اختبارات الرئيسية.
- نجحت 23 حالة parity مستهدفة، وبناء TypeScript/Vite، وحزم Go الخاصة بالمحتوى محليًا. بقي تحذير حجم bundle القائم. اختبارات PostgreSQL المحلية SKIPPED دون `DATABASE_URL`، ولا تُحسب دليل تخزين فعلي.
- أُضيفت رحلة متصفح بجلسة مدير حقيقية: تعديل الشعار والاسم من الشاشة، الحفظ، التحديث، عرض المدير ثم الزائر بلا cookies، رابط الرئيسية، ومقاسات390/820/1440. لا محاكاة لاستجابات الهوية أو CSRF أو homepage. كتالوج المحتوى وحده يستخدم fixtures فارغة لأنه خارج خادم العرض المعزول.
- وجدت المراجعة المستقلة سباقًا بين ملفي اختبار يعدلان singleton الإعدادات؛ أُصلح بتشغيلهما عبر `--workers=1`. لم تجد المراجعة عيبًا آخر ضمن النطاق.

## تحقيق المقارنة البصرية

رفضت المقارنة الأولى رسم النص رغم تطابق دائرة الشعار. أُضيف bootstrap الخطوط العام الذي كان غائبًا عن المرجع. أثبتت قياسات الجولة التالية تطابق مواقع العناصر وأبعادها والخطوط والألوان وتباعد الحروف، مع استمرار فرق رسم النص.

كان المرجع صفحة قصيرة، بينما الهيدر الحقيقي مثبت فوق صفحة قابلة للتمرير. أصبح جسم المرجع قابلًا للتمرير، ويُمرَّر المصدر والهدف ويُعادان إلى البداية قبل الالتقاط. بعد توحيد هذه الشروط نجحت المقارنات الست. لم تُضف أقنعة أو سماحية بكسلات، ولم يُعدّل CSS لإخفاء فرق.

هذه مقارنة لمرساة الشعار الأصلية مع مرساة Go تحت CSS وظروف التقاط موحدة. لا تثبت بقية الهيدر أو تطبيق المصدر كاملًا، ولا كل ظروف GPU والمتصفحات.
