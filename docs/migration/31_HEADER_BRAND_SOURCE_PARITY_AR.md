# 31 — حفظ الشعار وعرضه بجانب الاسم كما في الأصل

دفعة تابعة للخطة03 وعقد المالك، بعد عمل محرر الهوية في#155. النطاق: تعديل صورة الشعار واسم المنصة من محرر المدير → Go/PostgreSQL القائم → عرض الاثنين معًا للمدير والزائر بعد التحديث. لا إغلاق للهيدر الكامل أو بوابة الموقع العام.

## الفجوة وإعادة الاستخدام والإصلاح

المصدر `components/Header.tsx`، blob `c4e45e5d9bd485538036e98f70eac42471a8fa71`، يعرض الصورة الدائرية بجانب النص دائمًا. Go كان يختار الصورة أو النص؛ حفظ شعار أخفى الاسم وأعطى الصورة مقاسات مختلفة. أصلح العرض ليحفظ صورة36/44px ودائرة وحدود الأصل، ويحتفظ بالاسم والعبارة التكميلية. استُخدم محرر#155 وخدمة#154 والصلاحيات والجلسات والتخزين القائمة؛ لا دومين أوAPI أوschema جديد.

## التحقق وحدود الأدلة

- اختبار rendering فعلي للمكون: حالتا زائر/طالب فشلتا قبل الإصلاح ثم نجحتا، وحالة صورة فارغة ناجحة؛ ليست هذه الصور أو دليلًا على تخزين فعلي.
- 7 اختبارات شعار/رئيسية محلية ناجحة؛ TypeScript/build ناجح مع تحذير حجمbundle القائم.
- أضيفت رحلة متصفح لقاعدة PostgreSQL المعزولة: تسجيل مدير حقيقي، تعديل الشعار والنص وحفظهما من الشاشة، إعادة التحميل، عرض المدير ثم مسحcookies وعرض الزائر، رابط الرئيسية، و390/820/1440. لاmock للهوية أوCSRF أوhomepage؛ كتالوج المحتوى خارج خادم العرض المعزول فقطfixtures فارغة.
- مرجع الصورة يعيد مرساة الشعار الأصلية تحتCSS واحد، بقراءة قيمGo المخزنة. المقارنة تشمل مرساة الشعار فقط؛ لا تثبت التنقل أوالهيدر كاملًا أوالتطبيق القديم. يجب فحص الصور والنتيجة فيCI قبل الاعتماد؛ إنشاء الاختبار لا يعني نجاحه.
- رحلتا إعداداتsingleton تعملان بworker واحد لمنع سباق اختبارات عابر للملفات. اختباراتGo المحلية تحتاجGOROOT الصريح في هذه البيئة؛ الفحص الأول دونGOROOT فشل قبل تشغيل الاختبارات ولا يعد فشلًا للمنتج.
