## ما نُقل بالفعل في هذه الدفعة

| عنصر قديم | الجديد | مستوى التطابق |
| --- | --- | --- |
| `overview` — الملخص العام | API `directorOverview` وبطاقات من ستة عدادات | أسماء/قيم/تدرج الألوان وأيقونات نفس المصدر؛ البيانات من PostgreSQL |
| `students` — الطلاب | قسم مستقل يحتفظ بإضافة الطالب ونقله وتعديل بياناته وتعطيله | سلوك العمليات المنفذة سابقًا محفوظ؛ يتطلب `SCHOOL_STUDENTS_VIEW` |
| `classes` — الفصول | قسم مستقل يعرض الفصول ويتيح الإنشاء وإعادة التسمية | يتطلب `SCHOOL_CLASSES_MANAGE` و`SCHOOL_CORE` |
| `teachers` — المعلمون والتكليفات | قسم مستقل للتكليفات وإيقافها | يتطلب `SCHOOL_TEACHERS_ASSIGN` و`SCHOOL_CORE` |

خريطة التنقل تحتفظ بـ`البداية` و`إدارة المدرسة` وترتيب البنود الأربعة من Node، وبـbreadcrumb يوضح القسم الحالي. لا تعرض البنود الستة الأخرى كرابط حقيقي؛ انتقالها إلى Go متوقف على نقل API والصلاحيات لكل بند.

## حماية الاستخدام

- حساب لديه `SCHOOL_OVERVIEW_VIEW` فقط يقرأ أرقام الملخص دون أن يستدعي قوائم الطلاب أو الفصول أو المعلمين التي لم يفوض بها.
- مسارات التقارير والتدخلات غير المكتملة لا تظهر كرابط سريع في الملخص حتى لا يتجاوز المستخدم حارس الصلاحيات عبر رابط مباشر.
- قائمة الموضوعات تُطلب فقط عند وجود مدرسة مفوضة لوظيفة تكليف المعلمين.
- التحويل مدرسة أ ← ب ← أ يصفر بطاقات وبيانات المدرسة ونماذج التعديل وكلمة المرور المؤقتة **في نفس حدث اختيار المدرسة**، ويعيد القسم إلى الملخص كما في Node، ويتحقق من `overview.school.schoolId` قبل عرض أي رقم، كما يرفض ردود generation/visit القديمة. نموذج إضافة الطالب نفسه محروس بصلاحية الإضافة. لا يظهر الرقم صفر المصطنع أثناء الانتظار.
- بعد عملية تغيير مدرسية ناجحة يُعاد تحميل ملخص المدرسة النشطة فقط.

## اختبارات ملزمة للإغلاق

1. Frontend CI `npm run build` وTypeScript.
2. Playwright — ست بطاقات متطابقة مع JSON من المدرسة المرخصة، وحساب overview-only بلا طلبات غير مصرح بها.
3. Playwright — ترتيب التنقل، تبديل الأقسام، وصول رد متأخر أثناء أ→ب→أ، واستمرار CRUD القديم داخل الأقسام الجديدة.
   - حالة بلا أي تفويض لا تطلب API الملخص ولا تعرض روابط التفافية للصفحات الحساسة.
4. Playwright — منع `scrollWidth > innerWidth` عند عروض 360، 390، 430، 768، 1024، 1366، 1440، 1920 بكسل.
5. مراجعة صور الشاشة من Go مقابل Node **بنفس بيانات fixture والحالة**؛ الاختبار الآلي للعرض وحده لا يُثبت تطابقًا بصريًا تامًا. هذا الشرط مفتوح إلى أن تتوفر لقطات مرجعية معتمدة من الإصدار القديم.
