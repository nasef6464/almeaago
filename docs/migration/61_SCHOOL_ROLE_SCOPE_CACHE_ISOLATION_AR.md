## عقد الرحلة

المستخدم يبدل مدرسة أو دورًا، أو تُلغى عضويته/تكليفه/علاقة ولي الأمر بالطالب، ثم يطلب شاشة الدور مرة أخرى. يجب أن تُقرأ الصلاحيات والعلاقات من الخدمة المختصة، لا من نسخة HTTP مخزنة بعد الإلغاء. يظل فصل السلطات كما هو: عضوية المدرسة ليست تكليف المعلم وليست علاقة ولي الأمر وليست استحقاق التجارة.

| الدور/الشاشة | GET | السلطة الفعلية | المخرجات |
|---|---|---|---|
| مدير المدرسة / سياق العضوية | `/api/v1/schools/context` | Organizations application → SchoolContexts → Organizations repository / PostgreSQL | المدرسة والدور والصلاحيات والوحدات |
| المعلم / مساحة العمل | `/api/v1/schools/teacher-workspace` | Organizations application → TeacherWorkspace → Organizations repository / PostgreSQL | المدارس والتكليفات والفصول والمواد |
| ولي الأمر / علاقة الأبناء | `/api/v1/parents/authority` | Organizations application → ParentAuthority → Organizations repository / PostgreSQL | معرّفات الأبناء والعلاقات النشطة |

التصحيح محصور في `Cache-Control: private, no-store` لكل استجابة، **قبل المصادقة** أيضًا، حتى لا تخزن طبقات المتصفح أو الوسطاء بيانات نطاق مستخدم سابق أو استجابة رفض. لا يتغير JSON أو endpoint أو قرار التفويض أو محتوى قاعدة البيانات. لا يضمن هذا الهيدر وحده إعادة استعلام تطبيق React أو إلغاء التخزين داخل JavaScript؛ هذه اختبارات منفصلة مطلوبة.
