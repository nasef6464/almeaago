# ALMEAA Database Migrator & Integrity Guard

## الغرض
حماية سلامة مخطط PostgreSQL وكتابة البيانات فيه، وإثبات سلامة نقل الكيانات من MongoDB بتسوية موثقة على نسخة اختبار.

## متى تُستدعى هذه المهارة
- عند فحص أو كتابة أي ملف هجرة SQL (`migrations/*.sql`).
- عند التحقق من سلامة القيود والعلاقات بين الجداول (Foreign Keys & Cascades).
- عند مراجعة عمليات القفل التزامني (Concurrency Locks) في المعاملات المالية أو نقل الطلاب.

## القواعد الصارمة
1. **التكامل المرجعي الصارم:** كل جدول فرعي يجب أن يمتلك مفاتيح أجنبية صريحة تربطه بالجدول الأب مع تحديد سلوك `ON DELETE` بوضوح (CASCADE أو RESTRICT).
2. **منع الأقفال الميتة (Deadlock Prevention):** العمليات المتزامنة (مثل نقل الطلاب بين الفصول أو حجز المقاعد) يجب أن تستخدم تسلسلاً موحداً مع `SELECT ... FOR UPDATE` لضمان الذرية.
3. **تطابق الهجرة:** كل ملف `.up.sql` يجب أن يقابله ملف `.down.sql` صالح للاسترجاع دون كسر بنية البيانات.

## دليل المخطط ودليل نقل البيانات

- اختر لهجرة SQL قاعدة مؤقتة، وطبّق الهجرات ثم اختبر القيود والسيناريو المحسوس. نفّذ التراجع وإعادة التطبيق عندما يدعمهما نوع التغيير. سجّل أسماء الإصدارات والأوامر والنتائج وحدود الرجوع للبيانات القائمة.
- لبروفة MongoDB إلى PostgreSQL استخدم لقطة مصرح بها وبيئة معزولة. احفظ تعريف المصدر والنسخة وبصمتها، وطابق مفاتيح المصدر والهدف وتبعيات الاستيراد. جرّب الإعادة بعد انقطاع وتحقق من منع التكرار.
- سلّم تسوية بحسب الكيان تشمل الأعداد والمعرّفات والسجلات اليتيمة والعلاقات ونسخ الأسئلة والمحاولات والنتائج والصلاحيات وبصمات الملفات عند انطباقها. سجّل كل فرق وقرار تسويته. نجاح تطبيق SQL دليل للمخطط فقط.
- جرّب استعادة النسخة الاحتياطية وعودة التطبيق إلى الإصدار المتفق عليه داخل الاختبار، وسجّل الزمن والأثر. فرق غير مفسَّر في البيانات المطلوبة أو غياب دليل الاستعادة يبقي بوابة النقل مفتوحة. نقل الإنتاج يحتاج تفويضًا مستقلاً.
